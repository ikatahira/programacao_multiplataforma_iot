Django ORM

Banco de dados sem escrever SQL

📖 O que é ORM?

Object-Relational Mapper

O ORM do Django "traduz" classes Python em tabelas de banco de dados. Você cria uma classe Python e o Django transforma automaticamente em uma tabela com colunas, sem que você precise escrever uma única linha de SQL.

Antes do ORM

SQL manual

-- SQL puro (sem ORM)
SELECT * FROM galeria_fotografia
WHERE publicada = 1
ORDER BY data;
Com ORM Django

Python puro

# Python com Django ORM
Fotografia.objects
  .filter(publicada=True)
  .order_by('data')
🗃️

SQLite incluso: O Django vem configurado com SQLite — um banco de dados que fica em um único arquivo (db.sqlite3) no projeto. Perfeito para desenvolvimento e funciona direto no Codespace sem configuração adicional!

Criando o Model

galeria/models.py

✏️ Modelo completo de Fotografia

galeria/models.py

# galeria/models.py
from django.db import models
from datetime import datetime

class Fotografia(models.Model):

    OPCOES_CATEGORIA = [
        ("NEBULOSA", "Nebulosa"),
        ("ESTRELA",  "Estrela"),
        ("GALÁXIA",  "Galáxia"),
        ("PLANETA",  "Planeta"),
    ]

    nome     = models.CharField(max_length=100, null=False, blank=False)
    legenda  = models.CharField(max_length=150, null=False, blank=False)
    categoria = models.CharField(
        max_length=100, 
        choices=OPCOES_CATEGORIA, 
        default=''
    )
    descricao = models.TextField(null=False, blank=False)
    foto      = models.ImageField(upload_to="fotos/%Y/%m/%d/", blank=True)
    publicada = models.BooleanField(default=False)
    data_fotografia = models.DateTimeField(
        default=datetime.now, 
        blank=False
    )

    def __str__(self):
        return self.nome

Migrations

Criando a tabela no banco de dados

📖 O que são Migrations?

Controle de versão do banco de dados

As migrations são como um "histórico" de todas as alterações no banco de dados. Cada vez que você modifica um model, cria uma migration que descreve o que mudou. Assim, o banco é atualizado de forma controlada e rastreável.

⚡ Os dois comandos essenciais

makemigrations → migrate

  • makemigrations — gera o arquivo de migration 
    python manage.py makemigrations

    Analisa os models e cria um arquivo em galeria/migrations/0001_initial.py descrevendo o que precisa ser criado no banco.

  • migrate — aplica as mudanças no banco 
    python manage.py migrate

    Executa todas as migrations pendentes e cria/altera as tabelas no db.sqlite3.

🔁

Regra de ouro: sempre que modificar um model (adicionar/remover campo, alterar tipo), rode makemigrations seguido de migrate. É como um "git add + git commit" para o banco de dados.

from galeria.models import Fotografia

# Criar o objeto
foto = Fotografia(
    nome="Nebulosa de Carina",
    legenda="webbtelescope.org / NASA / James Webb",

)

foto.save()

# Verificar
Fotografia.objects.all()
🔍 Consultando dados

QuerySets — filtrando e ordenando

# Buscar todas as fotos
Fotografia.objects.all()

# Filtrar somente publicadas
Fotografia.objects.filter(publicada=True)

# Ordenar por data
Fotografia.objects.order_by("data_fotografia")

# Combinar filtro + ordenação
Fotografia.objects
    .filter(publicada=True)
    .order_by("data_fotografia")

# Buscar um item específico por ID
Fotografia.objects.get(pk=1)

Views com Banco de Dados

Substituindo dicionários por queries reais

✏️ views.py completo

Buscando dados reais do banco

# galeria/views.py
from django.shortcuts import render, get_object_or_404
from galeria.models import Fotografia

def index(request):
    fotografias = Fotografia.objects
        .order_by("data_fotografia")
        .filter(publicada=True)
    return render(
        request, 
        'galeria/index.html', 
        {"cards": fotografias}
    )

def imagem(request, foto_id):
    fotografia = get_object_or_404(Fotografia, pk=foto_id)
    return render(
        request, 
        'galeria/imagem.html', 
        {"fotografia": fotografia}
    )

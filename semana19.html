Consumo de APIs REST no Front-end

Use fetch, trate carregamento/erro, crie um hook useFetch reutilizável e dê os primeiros passos em GraphQL consumindo uma API pública real.

🎯 Objetivos de Aprendizagem

  • Revisar os conceitos de API REST: recursos, verbos HTTP, status codes e JSON;
  • Consumir uma API pública real dentro de um componente React com fetch;
  • Tratar estados de carregando / sucesso / erro corretamente (essencial para dados de sensores que podem falhar);
  • Criar um hook customizado (useFetch) para reaproveitar lógica de requisição;
  • Comparar rapidamente REST com GraphQL, conforme previsto na ementa da disciplina.

🧠 Revisão rápida: REST em uma página

Uma API REST expõe recursos através de URLs, e você interage com eles usando verbos HTTP:

  • GET — buscar dados (ex: última leitura de um sensor)
  • POST — criar um novo registro (ex: o ESP32 envia uma nova leitura)
  • PUT/PATCH — atualizar um registro existente
  • DELETE — remover um registro

As respostas normalmente vêm em JSON e trazem um status code: 200 OK, 201 criado, 400 erro do cliente, 404 não encontrado, 500 erro no servidor. Esses códigos serão importantes para tratarmos erros de conexão com sensores mais adiante.

🛠️ Passo a Passo — Consumindo uma API real no React

Vamos usar a Open-Meteo, uma API pública de dados meteorológicos, totalmente gratuita e sem necessidade de chave de API — perfeita para simular "dados de sensores ambientais" (temperatura, vento, umidade) vindos de fora da aplicação, exatamente como viria de um broker IoT.

2 Teste a API direto no navegador

Cole esta URL na barra de endereços do navegador (é uma requisição GET pura):

https://api.open-meteo.com/v1/forecast?latitude=-22.97&longitude=-49.87¤t=temperature_2m,relative_humidity_2m,wind_speed_10m

Você verá um JSON parecido com este (dados de Ourinhos/SP, mas pode trocar latitude/longitude pela sua cidade):

{
  "current": {
    "temperature_2m": 24.3,
    "relative_humidity_2m": 58,
    "wind_speed_10m": 9.4
  }
}

Perceba: isso é exatamente a forma como, mais adiante, você vai receber os dados de um sensor real — um objeto JSON com valores numéricos e um timestamp.

3 Criando o componente com fetch()

Crie src/PainelClima.jsx:

import { useState, useEffect } from 'react';

function PainelClima() {
  const [dados, setDados] = useState(null);
  const [carregando, setCarregando] = useState(true);
  const [erro, setErro] = useState(null);

  useEffect(() => {
    const url = 'https://api.open-meteo.com/v1/forecast?latitude=-22.97&longitude=-49.87¤t=temperature_2m,relative_humidity_2m,wind_speed_10m';

    fetch(url)
      .then(resposta => {
        if (!resposta.ok) throw new Error('Falha na requisição: ' + resposta.status);
        return resposta.json();
      })
      .then(json => {
        setDados(json.current);
        setCarregando(false);
      })
      .catch(err => {
        setErro(err.message);
        setCarregando(false);
      });
  }, []);

  if (carregando) return <p>Carregando dados do sensor climático...</p>;
  if (erro) return <p>Erro ao buscar dados: {erro}</p>;

  return (
    <div>
      <h2>Estação Climática</h2>
      <p>🌡️ Temperatura: {dados.temperature_2m} °C</p>
      <p>💧 Umidade: {dados.relative_humidity_2m}%</p>
      <p>🌬️ Vento: {dados.wind_speed_10m} km/h</p>
    </div>
  );
}

export default PainelClima;

Importe e use em App.jsx:

import PainelClima from './PainelClima';

function App() {
  return <PainelClima />;
}
export default App;
Por que os três estados (carregando / erro / dados)? Numa aplicação real conectada a sensores, a rede pode cair, o servidor pode demorar, o sensor pode estar offline. Tratar esses três casos desde já evita uma tela em branco quando algo falhar.
4 Criando um hook customizado — useFetch

Como toda requisição repete o mesmo padrão (carregando/erro/dados), vamos extrair isso para um hook reutilizável. Crie src/useFetch.js:

import { useState, useEffect } from 'react';

function useFetch(url) {
  const [dados, setDados] = useState(null);
  const [carregando, setCarregando] = useState(true);
  const [erro, setErro] = useState(null);

  useEffect(() => {
    setCarregando(true);
    fetch(url)
      .then(r => {
        if (!r.ok) throw new Error('HTTP ' + r.status);
        return r.json();
      })
      .then(json => { setDados(json); setCarregando(false); })
      .catch(err => { setErro(err.message); setCarregando(false); });
  }, [url]);

  return { dados, carregando, erro };
}

export default useFetch;

Agora PainelClima.jsx fica muito mais simples:

import useFetch from './useFetch';

function PainelClima() {
  const url = 'https://api.open-meteo.com/v1/forecast?latitude=-22.97&longitude=-49.87¤t=temperature_2m,relative_humidity_2m,wind_speed_10m';
  const { dados, carregando, erro } = useFetch(url);

  if (carregando) return <p>Carregando...</p>;
  if (erro) return <p>Erro: {erro}</p>;

  return (
    <div>
      <p>🌡️ {dados.current.temperature_2m} °C</p>
      <p>💧 {dados.current.relative_humidity_2m}%</p>
    </div>
  );
}
export default PainelClima;

Esse mesmo hook useFetch poderá ser reaproveitado para qualquer API REST futura da disciplina — inclusive a que vocês mesmos vão construir no Módulo 07 (Semanas 33–36).

5 Atualização periódica (polling)

Sensores reais mandam dados repetidamente. Adicione um setInterval que refaz a requisição a cada 60 segundos dentro do useFetch, ou crie uma variante usePolling:

useEffect(() => {
  function buscar() {
    fetch(url).then(r => r.json()).then(setDados);
  }
  buscar();
  const id = setInterval(buscar, 60000);
  return () => clearInterval(id);
}, [url]);
Isso é "polling": o cliente pergunta ao servidor de tempos em tempos. Funciona bem, mas gasta requisições à toa quando nada mudou. Na Semana 20 veremos o WebSocket, onde é o servidor quem avisa o cliente assim que há um dado novo — muito mais eficiente para IoT em tempo real.
6 Bônus — um gostinho de GraphQL

A ementa também cita GraphQL. A diferença central: em REST você recebe tudo que o endpoint devolve; em GraphQL você pede exatamente os campos que quer, em uma única requisição POST. Teste com a API pública de países:

fetch('https://countries.trevorblades.com/', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({
    query: `{ country(code: "BR") { name capital currency } }`
  })
})
  .then(r => r.json())
  .then(json => console.log(json.data.country));

Repare que a "query" define exatamente os campos name, capital e currency — nada a mais é retornado. Vamos aprofundar GraphQL no Módulo 07.

🌐 Painel de Dados Externos

Construa um painel que consome uma API pública real, tratando corretamente carregamento e erros.

📋 Instruções:

  1. Escolha uma API pública gratuita e sem necessidade de chave (Open-Meteo, ViaCEP, ou outra API REST livre à sua escolha);
  2. Implemente o hook useFetch reutilizável, conforme o passo a passo;
  3. Exiba os dados em pelo menos 2 componentes diferentes (ex: PainelClima e outro painel de sua escolha), reaproveitando o mesmo hook;
  4. Trate os três estados: carregando, erro (force um erro trocando a URL propositalmente e mostre a mensagem) e sucesso;
  5. Implemente atualização automática (polling) a cada 30–60 segundos em pelo menos um dos painéis;
  6. Escreva ao menos 1 teste automatizado mockando o fetch;
  7. Commit e push no mesmo repositório GitHub da Semana 18.
📦 Entregável: Link do repositório atualizado + print mostrando o estado de erro funcionando corretamente.

✅ Critérios de Avaliação:

  • Hook customizado funcional e reaproveitado em mais de um componente
  • Tratamento visível de carregando/erro/sucesso
  • Atualização periódica implementada corretamente (sem vazamento de intervalos)
  • Teste automatizado presente
  • Organização do código e histórico de commits

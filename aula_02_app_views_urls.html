Projeto vs App

Entendendo a estrutura do Django

🏗️ Projeto (setup)

Coleção de configurações

O projeto é o contêiner principal. Ele reúne todas as configurações, a lista de apps instaladas e as rotas principais. Um projeto pode ter vários apps.

settings.py urls.py wsgi.py
🧩 App (galeria)

Funcionalidade isolada

Um app é um pedaço independente do projeto com uma responsabilidade específica. A galeria de fotos é um app. Um sistema de login seria outro app.

models.py views.py urls.py
💡

Analogia: O projeto é como um prédio inteiro, e cada app é um apartamento com uma função específica. Um app pode até ser reutilizado em diferentes projetos!

Criando a App Galeria

python manage.py startapp

1️⃣ Criar a app

Comando startapp

# Criar o app "galeria"
python manage.py startapp galeria

Isso cria uma pasta galeria/ com vários arquivos prontos.

📂 Estrutura criada

O que foi gerado

galeria/
├── __init__.py
├── admin.py       # Configuração do Admin
├── apps.py        # Configurações do app
├── models.py      # Banco de dados
├── tests.py       # Testes automatizados
├── views.py       # Lógica das páginas
└── migrations/
    └── __init__.py
2️⃣ Registrar o app no projeto

Editar settings.py

O projeto precisa saber que a app galeria existe. Adicione ao INSTALLED_APPS:

# setup/settings.py
INSTALLED_APPS = [
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
    'galeria',   # ← adicione esta linha
]
💡

Boa prática: você pode referenciar o app com sua configuração completa: 'galeria.apps.GaleriaConfig'. Isso é mais preciso e é o padrão de mercado.

Views — A Lógica das Páginas

Funções que processam requisições e retornam respostas

📖 O que é uma View?

Funções Python que respondem a requisições HTTP

Uma view recebe um request (pedido do navegador) e retorna uma response (resposta com o conteúdo HTML). É aqui que fica a lógica da sua página.

✏️ Primeira view

galeria/views.py

# galeria/views.py
from django.shortcuts import render

def index(request):
    return render(request, 'galeria/index.html')

def imagem(request):
    return render(request, 'galeria/imagem.html')

A função render() junta o request com o template HTML e retorna a página pronta para o navegador.

🔎

render(request, template, contexto) — o terceiro parâmetro (opcional) é um dicionário que passa dados do Python para o HTML. Usaremos isso na Aula 03!

URLs — O Sistema de Rotas

Conectando endereços web às suas views

1️⃣ Criar urls.py na galeria

Boa prática: cada app tem suas próprias rotas

Crie um novo arquivo galeria/urls.py:

# galeria/urls.py
from django.urls import path
from galeria.views import index, imagem

urlpatterns = [
    path('', index, name='index'),
    path('imagem/', imagem, name='imagem'),
]
2️⃣ Conectar ao urls.py principal

setup/urls.py — incluindo as rotas da galeria

# setup/urls.py
from django.contrib import admin
from django.urls import path, include

urlpatterns = [
    path('admin/', admin.site.urls),
    path('', include('galeria.urls')),
]
💡

include() importa todas as rotas do arquivo galeria/urls.py. Isso mantém o projeto organizado: cada app gerencia suas próprias URLs, e o urls.py principal apenas delega.

🏷️ URL com nome (name)

Por que nomear as URLs?

Com nomes nas rotas, você usa {% url 'imagem' %} nos templates ao invés de escrever o caminho diretamente. Se a URL mudar, só precisa alterar em um lugar!

<!-- No template HTML, use assim: -->
<a href="{% url 'index' %}">Home</a>
<a href="{% url 'imagem' %}">Ver imagem</a>

Templates — O HTML do Django

Configurando e organizando os arquivos HTML

1️⃣ Configurar a pasta de templates

settings.py — informando onde ficam os HTMLs

# setup/settings.py
TEMPLATES = [
    {
        'BACKEND': 'django.template.backends.django.DjangoTemplates',
        'DIRS': [os.path.join(BASE_DIR, 'templates')],  # ← esta linha
        'APP_DIRS': True,
        ...
    },
]
📂 Estrutura de pastas

Organização dos templates

templates/
└── galeria/
    ├── base.html      # Template base (evita repetição)
    ├── index.html     # Página inicial
    └── imagem.html    # Página de detalhe
2️⃣ Template base — DRY

Don't Repeat Yourself

O base.html contém a estrutura HTML que se repete em todas as páginas (head, menu, footer). Os outros templates "herdam" dele:

<!-- templates/galeria/base.html -->
<!DOCTYPE html>
<html lang="pt-BR">
<head>
    <title>Space Gallery</title>
    <!-- CSS, fonts etc. -->
</head>
<body>
    {% block content %}{% endblock %}
</body>
</html>
<!-- templates/galeria/index.html -->
{% extends 'galeria/base.html' %}
{% load static %}

{% block content %}
  <main>
    <h1>Galeria de Imagens</h1>
    <!-- conteúdo específico desta página -->
  </main>
{% endblock %}
3️⃣ Partials — fragmentos reutilizáveis

Menu e footer separados

Código como o menu lateral e footer pode ser isolado em partials e incluído com {% include %}:

templates/galeria/
└── partials/
    ├── _menu.html
    └── _footer.html
<!-- No base.html, inclua as partials assim: -->
{% include 'galeria/partials/_menu.html' %}
{% include 'galeria/partials/_footer.html' %}

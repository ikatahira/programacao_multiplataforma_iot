Progressive Web Apps (PWA) — Offline-First

Transforme o dashboard IoT em uma PWA instalável e resiliente a quedas de rede, usando manifest, Service Worker e estratégias de cache — fechando o Módulo 04.

🎯 Objetivos de Aprendizagem

  • Entender o que é uma Progressive Web App (PWA) e por que ela importa para dashboards IoT;
  • Criar o manifest e tornar o dashboard instalável;
  • Registrar um Service Worker e entender estratégias de cache;
  • Transformar o Dashboard IoT das semanas anteriores em uma PWA offline-first;
  • Testar o comportamento offline dentro do próprio StackBlitz e fechar o Módulo 04 com o projeto completo no GitHub.
🔄 Retomando de onde parou?

Você está usando um computador de laboratório diferente do da semana passada? Sem problema — nada foi instalado localmente, então nada fica "preso" numa máquina.

  1. Abra o Edge (ou Chrome) e acesse stackblitz.com;
  2. Clique em Sign in (canto superior direito) → Continue with GitHub → entre com a mesma conta GitHub da semana passada;
  3. Se preferir reabrir direto pelo repositório: acesse https://stackblitz.com/github/SEU-USUARIO/dashboard-iot-isw044 — isso importa seu repositório do GitHub direto para um ambiente StackBlitz novo, pronto para editar;
  4. No terminal do projeto, rode npm install uma vez (garante que todas as dependências estão presentes) e depois npm run dev.

Não lembra o passo a passo completo de configuração do ambiente? Ele está detalhado na Semana 18.

🧠 Por que offline-first em um dashboard IoT?

Redes falham — Wi-Fi cai, o sinal oscila, o servidor reinicia. Um dashboard de sensores que simplesmente trava numa tela branca quando a conexão cai é uma péssima experiência.

Uma PWA é uma aplicação web que se comporta como um app nativo: pode ser instalada e mantém em cache a última versão da interface e dos últimos dados recebidos. Isso fecha o Módulo 04 conectando de volta com a exigência de "aplicações web responsivas" da ementa — responsivo também é sobre resiliência de rede.

🛠️ Passo a Passo — Transformando o Dashboard em PWA

1 Instale o plugin oficial de PWA pelo terminal do StackBlitz
npm install -D vite-plugin-pwa
2 Configure o plugin em vite.config.js

Abra vite.config.js e acrescente o plugin de PWA, mantendo o proxy da Semana 20:

import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';
import { VitePWA } from 'vite-plugin-pwa';

export default defineConfig({
  plugins: [
    react(),
    VitePWA({
      registerType: 'autoUpdate',
      manifest: {
        name: 'Dashboard IoT — ISW044',
        short_name: 'DashboardIoT',
        description: 'Monitoramento de sensores em tempo real',
        theme_color: '#0c0f1a',
        background_color: '#0c0f1a',
        display: 'standalone',
        icons: [
          { src: 'icon-192.png', sizes: '192x192', type: 'image/png' },
          { src: 'icon-512.png', sizes: '512x512', type: 'image/png' },
        ],
      },
      workbox: {
        runtimeCaching: [
          {
            urlPattern: /^https:\/\/api\.open-meteo\.com\/.*/,
            handler: 'NetworkFirst',
            options: { cacheName: 'api-clima-cache' },
          },
        ],
      },
    }),
  ],
  server: {
    proxy: {
      '/ws': { target: 'ws://localhost:8080', ws: true },
    },
  },
});
3 Adicione os ícones do app

No explorador de arquivos, abra a pasta public (se não existir, crie-a na raiz). Você precisa de dois arquivos de imagem simples: icon-192.png (192×192 pixels) e icon-512.png (512×512 pixels). Gere-os rapidamente em qualquer gerador de ícone/favicon gratuito online e faça o upload arrastando os arquivos para dentro da pasta public no StackBlitz (o explorador de arquivos aceita arrastar e soltar do seu computador).

4 Entenda o que o plugin faz por trás

O vite-plugin-pwa gera automaticamente, no build de produção, dois arquivos essenciais:

  • manifest — descreve o app (nome, ícone, cor, modo de exibição) para o navegador saber como "instalá-lo";
  • service worker — um script que roda em segundo plano, intercepta requisições de rede e decide se responde com algo em cache ou busca na internet.
5 Estratégias de cache — qual usar em cada caso
  • Cache First: usa o cache se existir, só vai à rede se não tiver nada salvo. Ideal para arquivos estáticos (CSS, ícones, fontes);
  • Network First: tenta a rede primeiro, cai para o cache se falhar. Ideal para dados de sensores/API — configuramos assim no passo 2;
  • Stale-While-Revalidate: mostra o cache imediatamente enquanto busca uma versão nova em segundo plano.
6 Salvando a última leitura para exibir offline

Ajuste useSensorStream.js para persistir a última leitura no localStorage:

socket.onmessage = (evento) => {
  const leitura = JSON.parse(evento.data);
  localStorage.setItem('ultimaLeitura', JSON.stringify(leitura));
  setHistorico(anterior => [...anterior.slice(-19), leitura]);
};

// ao iniciar o hook, antes de qualquer conexão:
const [ultimaSalva] = useState(() => {
  const salvo = localStorage.getItem('ultimaLeitura');
  return salvo ? JSON.parse(salvo) : null;
});

Assim, mesmo sem internet, o dashboard abre mostrando a última leitura conhecida em vez de uma tela vazia.

7 Indicando o status online/offline na interface

Crie src/useOnlineStatus.js:

import { useState, useEffect } from 'react';

function useOnlineStatus() {
  const [online, setOnline] = useState(navigator.onLine);

  useEffect(() => {
    const setOn = () => setOnline(true);
    const setOff = () => setOnline(false);
    window.addEventListener('online', setOn);
    window.addEventListener('offline', setOff);
    return () => {
      window.removeEventListener('online', setOn);
      window.removeEventListener('offline', setOff);
    };
  }, []);

  return online;
}

export default useOnlineStatus;

Use no Dashboard: {!online && <div>⚠️ Você está offline — exibindo últimos dados salvos</div>}.

8 Gerando o build de produção

O Service Worker só funciona de forma completa em build de produção (não no modo dev). No package.json, ajuste também o script de preview para subir o servidor junto:

"scripts": {
  "dev": "concurrently \"node servidor.js\" \"vite\"",
  "build": "vite build",
  "preview": "concurrently \"node servidor.js\" \"vite preview\""
}

No terminal:

npm run build
npm run preview

Abra o Preview em uma aba separada do navegador.

9 Testando o modo offline

Na aba com o Preview aberto, pressione F12 para abrir o DevTools → aba Application (Chrome/Edge) → Service Workers no menu lateral → confirme que está "activated and running". Depois vá em Network e marque a caixa Offline. Recarregue a página: ela deve continuar abrindo, mostrando a última leitura salva, mesmo sem rede.

10 Instalando como app

Ainda no Chrome/Edge, procure o ícone de instalação na barra de endereço (ou menu ⋮ → "Instalar app" / "Apps → Instalar este site como app"). O dashboard abrirá em uma janela própria, sem a barra do navegador.

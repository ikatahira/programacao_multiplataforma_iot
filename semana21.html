Dashboard de Sensores IoT com React

Consolide componentes, hooks e WebSocket em um dashboard completo com gráficos de histórico e layout responsivo — pronto para receber dados de um ESP32 real.

🎯 Objetivos de Aprendizagem

  • Consolidar os conhecimentos das Semanas 18–20 em um dashboard IoT completo;
  • Entender a arquitetura ponta a ponta: sensor (ESP32/Arduino) → broker/servidor → WebSocket → React;
  • Exibir múltiplos sensores com gráficos de histórico usando Chart.js;
  • Organizar o layout de forma responsiva (mobile-first);
  • Preparar o projeto para ligação com hardware real (ESP32) quando disponível no laboratório.
📖 Glossário desta semana — clique para expandir (12 termos)
arquitetura (de software)
O "desenho" geral de como as partes de um sistema se conectam e se comunicam — ex: sensor → servidor → WebSocket → dashboard.
Chart.js
Uma biblioteca JavaScript popular para desenhar gráficos (linhas, barras, pizza) em páginas web.
react-chartjs-2
Um "adaptador" que permite usar a biblioteca Chart.js como componentes React, de forma mais natural dentro do código.
responsivo (design)
Um layout que se adapta automaticamente a diferentes tamanhos de tela (celular, tablet, monitor), sem quebrar ou ficar cortado.
mobile-first
Estratégia de projetar primeiro pensando em telas pequenas (celular) e depois adaptar para telas maiores — em vez do caminho inverso.
CSS Grid
Um sistema de layout do CSS que organiza elementos em linhas e colunas, útil para grades de cards e painéis responsivos.
DevTools
Developer Tools — o painel de ferramentas para desenvolvedores embutido no navegador (abre com a tecla F12), usado para inspecionar, depurar e testar sites.
caso de borda (edge case)
Uma situação incomum ou extrema que o código precisa tratar corretamente — ex: uma lista de histórico vazia antes do primeiro dado chegar.
mineração de dados em tempo real
Extrair informações úteis (médias, tendências, alertas) de um fluxo contínuo de dados, à medida que eles chegam — em vez de só armazená-los sem análise.
useMemo
Hook do React que guarda em cache (memoriza) o resultado de um cálculo, refazendo-o só quando algo do qual ele depende realmente muda.
escalabilidade horizontal
Aumentar a capacidade de um sistema adicionando mais instâncias/máquinas rodando em paralelo, em vez de deixar uma única máquina mais potente.
Web Serial API
API do navegador que permite ler/escrever diretamente numa porta serial (USB), como a de um Arduino, sem precisar de um servidor no meio.

🧠 Arquitetura do Dashboard IoT

Esta semana fecha o ciclo iniciado na Semana 18. O fluxo completo de dados, do sensor físico até a tela do usuário, tem duas variantes possíveis:

Caminho A — sensor simulado ou em rede (o que já construímos):
[ Sensor simulado / ESP32 em rede ]
        ▼
[ Servidor / Broker ]   ← nosso servidor.js com WebSocket, dentro do mesmo projeto StackBlitz
        │                  (no Módulo 06 veremos MQTT/RabbitMQ/Kafka)
        ▼
[ WebSocket via /ws (proxy do Vite) ]
        ▼
[ Dashboard React ]
        ▼
  Usuário vê os gráficos ao vivo

Caminho B — sensor real via USB (Semana 20, bônus):
[ Arduino Uno + fototransistor ] → cabo USB
        ▼
[ Web Serial API ]  ← lida direto pelo navegador, sem servidor
        ▼
[ Dashboard React ]
        ▼
  Usuário vê o dado real ao vivo

Repare que, nos dois casos, o componente React que desenha o gráfico não muda nada — ele só espera receber um objeto com os valores. Essa separação entre "de onde o dado vem" e "como o dado é exibido" é um dos princípios mais importantes de sistemas distribuídos: trocar a fonte de dados não deveria exigir reescrever a interface.

🔀 Ligando os dois mundos: simulado e real, lado a lado

Se você fez o bônus da Semana 20 (Arduino + Web Serial), pode oferecer no dashboard um seletor de fonte de dados, deixando claro para o usuário se ele está vendo dados simulados ou o sensor físico de verdade:

import { useState } from 'react';
import useSensorStream from './useSensorStream';   // Caminho A — WebSocket simulado
import useSerialSensor from './useSerialSensor';   // Caminho B — Web Serial real

function Dashboard() {
  const [fonte, setFonte] = useState('simulado'); // 'simulado' | 'real'

  const simulado = useSensorStream(20);
  const real = useSerialSensor();

  return (
    <div style={{ padding: 24 }}>
      <div style={{ marginBottom: 16 }}>
        <button onClick={() => setFonte('simulado')}>📡 Simulado</button>
        <button onClick={() => setFonte('real')}>🔌 Sensor Real (USB)</button>
      </div>

      {fonte === 'simulado' && (
        <p>Conectado: {simulado.conectado ? '🟢' : '🔴'} — Temperatura: {simulado.ultimo?.temperatura} °C</p>
      )}

      {fonte === 'real' && (
        <>
          {!real.conectado && <button onClick={real.conectar}>Conectar Arduino</button>}
          {real.leitura && <p>{real.leitura.mensagem} (pino: {real.leitura.estadoPino})</p>}
        </>
      )}
    </div>
  );
}

export default Dashboard;

Essa alternância explícita entre fonte simulada e fonte real é ótima para demonstrações e defesas de projeto: você mostra que o sistema funciona igual dos dois lados, provando que a arquitetura está desacoplada corretamente.

3 Crie um hook para acumular histórico por sensor

Crie src/useSensorStream.js (baseado no useWebSocket da Semana 20):

import { useState, useEffect } from 'react';

function useSensorStream(limite = 20) {
  const [historico, setHistorico] = useState([]);
  const [conectado, setConectado] = useState(false);

  useEffect(() => {
    const protocolo = window.location.protocol === 'https:' ? 'wss://' : 'ws://';
    const socket = new WebSocket(protocolo + window.location.host + '/ws');
    socket.onopen = () => setConectado(true);
    socket.onclose = () => setConectado(false);
    socket.onmessage = (evento) => {
      const leitura = JSON.parse(evento.data);
      setHistorico(anterior => [...anterior.slice(-(limite - 1)), leitura]);
    };
    return () => socket.close();
  }, [limite]);

  return { historico, conectado, ultimo: historico[historico.length - 1] };
}

export default useSensorStream;
4 Mineração de dados em tempo real: média, mínimo e máximo

Só mostrar o dado bruto que chega já é útil, mas a ementa da disciplina pede especificamente mineração de dados em tempo real (data streaming) — ou seja, extrair informação do fluxo de dados, não só empilhar leituras. Vamos calcular estatísticas simples sobre o histórico que já estamos guardando. Ajuste useSensorStream.js:

import { useState, useEffect, useMemo } from 'react';

function useSensorStream(limite = 20) {
  const [historico, setHistorico] = useState([]);
  const [conectado, setConectado] = useState(false);

  useEffect(() => {
    const protocolo = window.location.protocol === 'https:' ? 'wss://' : 'ws://';
    const socket = new WebSocket(protocolo + window.location.host + '/ws');
    socket.onopen = () => setConectado(true);
    socket.onclose = () => setConectado(false);
    socket.onmessage = (evento) => {
      const leitura = JSON.parse(evento.data);
      setHistorico(anterior => [...anterior.slice(-(limite - 1)), leitura]);
    };
    return () => socket.close();
  }, [limite]);

  // "Mineração" simples: calcula estatísticas do fluxo sempre que o histórico muda
  const estatisticas = useMemo(() => {
    function calcular(campo) {
      const valores = historico.map(h => h[campo]).filter(v => typeof v === 'number');
      if (valores.length === 0) return null;
      const soma = valores.reduce((acc, v) => acc + v, 0);
      return {
        media: +(soma / valores.length).toFixed(1),
        minimo: Math.min(...valores),
        maximo: Math.max(...valores),
      };
    }
    return {
      temperatura: calcular('temperatura'),
      umidade: calcular('umidade'),
      luminosidade: calcular('luminosidade'),
    };
  }, [historico]);

  return { historico, conectado, ultimo: historico[historico.length - 1], estatisticas };
}

export default useSensorStream;

O hook useMemo recalcula a média/mínimo/máximo somente quando o histórico muda, evitando refazer essa conta a cada re-renderização sem necessidade. Isso é o começo de uma pipeline de streaming analytics — ferramentas como o InfluxDB/Grafana do Módulo 07 (Semanas 33–36) fazem exatamente esse tipo de agregação, só que em escala e com janelas de tempo configuráveis (última hora, último dia, etc.), em vez de só as últimas N leituras em memória.

Vá além (opcional): tente adicionar um alerta simples — por exemplo, destacar em vermelho quando estatisticas.temperatura.maximo ultrapassar um limiar, tipo 30°C. Isso já é uma forma (bem simples) de detecção de padrão em tempo real.
5 Componente de gráfico reutilizável

Crie src/GraficoSensor.jsx:

import { Line } from 'react-chartjs-2';
import {
  Chart as ChartJS, LineElement, PointElement,
  CategoryScale, LinearScale, Tooltip,
} from 'chart.js';

ChartJS.register(LineElement, PointElement, CategoryScale, LinearScale, Tooltip);

function GraficoSensor({ titulo, historico, campo, cor, estatisticas }) {
  const dados = {
    labels: historico.map(h => new Date(h.timestamp).toLocaleTimeString()),
    datasets: [{
      label: titulo,
      data: historico.map(h => h[campo]),
      borderColor: cor,
      tension: 0.3,
    }],
  };

  return (
    <div style={{ background: '#181d2f', padding: 16, borderRadius: 10 }}>
      <h3>{titulo}</h3>
      <Line data={dados} />
      {estatisticas && (
        <p style={{ fontSize: 12, opacity: 0.8, marginTop: 8 }}>
          média: {estatisticas.media} · mín: {estatisticas.minimo} · máx: {estatisticas.maximo}
        </p>
      )}
    </div>
  );
}

export default GraficoSensor;

Se sua turma tiver placas ESP32 disponíveis (materiais de apoio "ESP32 — Missão IoT" no índice do curso) conectadas à mesma rede Wi-Fi, o caminho é diferente do Arduino via USB: o ESP32 enviaria leituras via HTTP POST para uma rota adicionada ao servidor.js, que retransmite via WebSocket para os clientes — isso será formalizado com um broker de verdade (MQTT) no Módulo 06.

9 (Opcional) Acoplando o circuito de botões + LEDs + DS18B20

Se você montou o circuito extra com 4 botões, 2 LEDs e um sensor de temperatura DS18B20, dá para acoplar a temperatura real dele nesta mesma tela, do mesmo jeito que o item anterior faz com o fototransistor: reaproveitando a Web Serial API e o mesmo componente GraficoSensor — só muda de onde o dado vem.

Passo 1 — Fazer o Arduino falar JSON. O sketch original desse circuito imprime linhas de texto soltas no Monitor Serial, ótimas para depurar mas difíceis de interpretar no navegador. Troque o bloco de Serial.print do final do loop() por uma única linha em JSON:

// Substitui os Serial.print de depuração por uma linha JSON,
// que o navegador consegue interpretar com JSON.parse()
Serial.print(F("{\"temperatura\":"));
Serial.print(temperaturaC);
Serial.print(F(",\"botao1\":")); Serial.print(botao1Pressionado);
Serial.print(F(",\"botao2\":")); Serial.print(botao2Pressionado);
Serial.print(F(",\"botao3\":")); Serial.print(botao3Pressionado);
Serial.print(F(",\"botao4\":")); Serial.print(botao4Pressionado);
Serial.println(F("}"));
Dica: mantenha esse Serial.println dentro do bloco que já roda a cada INTERVALO_LEITURA (1 leitura por segundo) — mandar uma linha por segundo é mais que suficiente para o gráfico e evita encher o buffer serial.

Passo 2 — Criar um hook no mesmo formato do useSensorStream. Crie src/useSerialSensor.js retornando exatamente as mesmas chaves (historico, conectado, ultimo, estatisticas) — assim o GraficoSensor não precisa saber se o dado é simulado ou real:

import { useState, useRef, useCallback, useMemo } from 'react';

function useSerialSensor(limite = 20) {
  const [historico, setHistorico] = useState([]);
  const [conectado, setConectado] = useState(false);
  const portaRef = useRef(null);

  const conectar = useCallback(async () => {
    try {
      const porta = await navigator.serial.requestPort();
      await porta.open({ baudRate: 9600 });
      portaRef.current = porta;
      setConectado(true);

      const decoder = new TextDecoderStream();
      porta.readable.pipeTo(decoder.writable);
      const leitor = decoder.readable.getReader();

      let buffer = '';
      while (true) {
        const { value, done } = await leitor.read();
        if (done) break;
        buffer += value;
        let fimDaLinha;
        while ((fimDaLinha = buffer.indexOf('\n')) >= 0) {
          const linha = buffer.slice(0, fimDaLinha).trim();
          buffer = buffer.slice(fimDaLinha + 1);
          if (!linha) continue;
          try {
            const leitura = { timestamp: new Date().toISOString(), ...JSON.parse(linha) };
            setHistorico(anterior => [...anterior.slice(-(limite - 1)), leitura]);
          } catch {
            // linha ainda incompleta ou corrompida — ignora e espera a próxima
          }
        }
      }
    } catch (erro) {
      console.error('Erro ao conectar na porta serial:', erro);
      setConectado(false);
    }
  }, [limite]);

  const estatisticas = useMemo(() => {
    function calcular(campo) {
      const valores = historico.map(h => h[campo]).filter(v => typeof v === 'number');
      if (valores.length === 0) return null;
      const soma = valores.reduce((acc, v) => acc + v, 0);
      return { media: +(soma / valores.length).toFixed(1), minimo: Math.min(...valores), maximo: Math.max(...valores) };
    }
    return { temperatura: calcular('temperatura') };
  }, [historico]);

  return { historico, conectado, conectar, ultimo: historico[historico.length - 1], estatisticas };
}

export default useSerialSensor;

  return (

          <GraficoSensor
            titulo="Temperatura Real (DS18B20)"

Repare que GraficoSensor não foi alterado em nenhuma linha — só passou a receber real.historico em vez de historico. É a mesma separação "de onde o dado vem" × "como é exibido" discutida lá em cima, só que agora com hardware que você mesmo montou.

Atenção: a Web Serial API só funciona em navegadores baseados em Chromium (Chrome, Edge) e exige HTTPS ou localhost — dentro do StackBlitz normalmente funciona, mas se der erro de permissão, teste rodando o projeto localmente.

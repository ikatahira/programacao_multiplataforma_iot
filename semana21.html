Dashboard de Sensores IoT com React

Consolide componentes, hooks e WebSocket em um dashboard completo com gráficos de histórico e layout responsivo — pronto para receber dados de um ESP32 real.

🎯 Objetivos de Aprendizagem

  • Consolidar os conhecimentos das Semanas 18–20 em um dashboard IoT completo;
  • Entender a arquitetura ponta a ponta: sensor (ESP32/Arduino) → broker/servidor → WebSocket → React;
  • Exibir múltiplos sensores com gráficos de histórico usando Chart.js;
  • Organizar o layout de forma responsiva (mobile-first);
  • Preparar o projeto para ligação com hardware real (ESP32) quando disponível no laboratório.
🔄 Retomando de onde parou?

Você está usando um computador de laboratório diferente do da semana passada? Sem problema — nada foi instalado localmente, então nada fica "preso" numa máquina.

  1. Abra o Edge (ou Chrome) e acesse stackblitz.com;
  2. Clique em Sign in (canto superior direito) → Continue with GitHub → entre com a mesma conta GitHub da semana passada;
  3. Se preferir reabrir direto pelo repositório: acesse https://stackblitz.com/github/SEU-USUARIO/dashboard-iot-isw044 — isso importa seu repositório do GitHub direto para um ambiente StackBlitz novo, pronto para editar;
  4. No terminal do projeto, rode npm install uma vez (garante que todas as dependências estão presentes) e depois npm run dev.

Não lembra o passo a passo completo de configuração do ambiente? Ele está detalhado na Semana 18.

🧠 Arquitetura do Dashboard IoT

Esta semana fecha o ciclo iniciado na Semana 18. O fluxo completo de dados, do sensor físico até a tela do usuário, é:

[ ESP32 / Arduino ]
        │  mede temperatura, umidade, luz...
        ▼
[ Servidor / Broker ]   ← nosso servidor.js com WebSocket, dentro do mesmo projeto StackBlitz
        │                  (no Módulo 06 veremos MQTT/RabbitMQ/Kafka)
        ▼
[ WebSocket via /ws (proxy do Vite) ]
        ▼
[ Dashboard React ]  ← o que vamos construir agora
        │
        ▼
  Usuário vê os gráficos ao vivo

Se o laboratório já tiver placas ESP32 disponíveis, o servidor.js pode receber dados reais via HTTP POST em vez de Math.random() — a interface React não muda nada, pois ela só depende do formato JSON da mensagem.

🛠️ Passo a Passo — Do WebSocket ao gráfico

1 Expanda o servidor para múltiplos sensores

No StackBlitz, abra servidor.js (raiz do projeto) e envie um objeto com vários sensores de uma vez:

const intervalo = setInterval(() => {

    temperatura: +(20 + Math.random() * 10).toFixed(1),

    luminosidade: +(200 + Math.random() * 400).toFixed(0),
  };
  socket.send(JSON.stringify(leitura));
}, 2000);
2 Instale o Chart.js pelo terminal do StackBlitz
npm install chart.js react-chartjs-2
3 Crie um hook para acumular histórico por sensor

Crie src/useSensorStream.js (baseado no useWebSocket da Semana 20):

import { useState, useEffect } from 'react';

function useSensorStream(limite = 20) {
  const [historico, setHistorico] = useState([]);
  const [conectado, setConectado] = useState(false);

  useEffect(() => {
    const protocolo = window.location.protocol === 'https:' ? 'wss://' : 'ws://';
    const socket = new WebSocket(protocolo + window.location.host + '/ws');
    socket.onopen = () => setConectado(true);
    socket.onclose = () => setConectado(false);
    socket.onmessage = (evento) => {
      const leitura = JSON.parse(evento.data);
      setHistorico(anterior => [...anterior.slice(-(limite - 1)), leitura]);
    };
    return () => socket.close();
  }, [limite]);

  return { historico, conectado, ultimo: historico[historico.length - 1] };
}

export default useSensorStream;
4 Componente de gráfico reutilizável

Crie src/GraficoSensor.jsx:

import { Line } from 'react-chartjs-2';
import {
  Chart as ChartJS, LineElement, PointElement,
  CategoryScale, LinearScale, Tooltip,
} from 'chart.js';

ChartJS.register(LineElement, PointElement, CategoryScale, LinearScale, Tooltip);

function GraficoSensor({ titulo, historico, campo, cor }) {
  const dados = {
    labels: historico.map(h => new Date(h.timestamp).toLocaleTimeString()),
    datasets: [{
      label: titulo,
      data: historico.map(h => h[campo]),
      borderColor: cor,
      tension: 0.3,
    }],
  };

  return (
    <div style={{ background: '#181d2f', padding: 16, borderRadius: 10 }}>
      <h3>{titulo}</h3>
      <Line data={dados} />
    </div>
  );
}

export default GraficoSensor;
5 Montando o dashboard final
import useSensorStream from './useSensorStream';
import GraficoSensor from './GraficoSensor';

function Dashboard() {
  const { historico, conectado, ultimo } = useSensorStream(20);

  return (
    <div style={{ padding: 24 }}>
      <h1>Dashboard IoT {conectado ? '🟢' : '🔴'}</h1>

      {ultimo && (
        <div style={{ display: 'flex', gap: 16, marginBottom: 24 }}>
          <div>🌡️ {ultimo.temperatura} °C</div>
          <div>💧 {ultimo.umidade}%</div>
          <div>💡 {ultimo.luminosidade} lux</div>
        </div>
      )}

      <div style={{
        display: 'grid',
        gridTemplateColumns: 'repeat(auto-fit, minmax(280px, 1fr))',
        gap: 20
      }}>
        <GraficoSensor titulo="Temperatura (°C)" historico={historico} campo="temperatura" cor="#f97316" />
        <GraficoSensor titulo="Umidade (%)" historico={historico} campo="umidade" cor="#4f8cff" />
        <GraficoSensor titulo="Luminosidade (lux)" historico={historico} campo="luminosidade" cor="#fbbf24" />
      </div>
    </div>
  );
}

export default Dashboard;

Use <Dashboard /> em App.jsx no lugar do componente da semana passada. Repare no gridTemplateColumns: 'repeat(auto-fit, minmax(280px, 1fr))': isso faz o layout se reorganizar sozinho conforme o tamanho da tela — a base da responsividade exigida na ementa.

6 Testando a responsividade

Abra o Preview em uma aba separada (ícone no canto do painel), pressione F12 para abrir o DevTools do navegador, clique no ícone de "alternar visualização de dispositivo" (parece um celular/tablet, geralmente Ctrl+Shift+M no Edge/Chrome) e teste em diferentes tamanhos de tela.

7 (Opcional) Conectando um ESP32 real

Se sua turma já tem placas ESP32 disponíveis (materiais de apoio "ESP32 — Missão IoT" no índice do curso), o ESP32 pode enviar leituras via HTTP POST para uma rota adicionada ao servidor.js (usando express), que por sua vez retransmite via WebSocket para os clientes conectados. Isso normalmente exige que o ESP32 esteja na mesma rede que consegue alcançar o endereço público do seu projeto StackBlitz — combine com o professor a melhor forma de testar isso no laboratório (pode envolver expor o servidor via um serviço de túnel, o que será visto com mais detalhe no Módulo 06).

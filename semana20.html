WebSocket e Dados em Tempo Real

Monte um servidor WebSocket em Node.js simulando sensores e conecte um cliente React para receber dados ao vivo — a base da comunicação em tempo real de sistemas distribuídos.

🎯 Objetivos de Aprendizagem

  • Entender a diferença entre polling HTTP e WebSocket para dados em tempo real;
  • Relacionar WebSocket com os conceitos de Sistemas Distribuídos da ementa (concorrência, comunicação assíncrona);
  • Criar um servidor WebSocket simples em Node.js que simula um sensor publicando dados;
  • Conectar um componente React ao servidor e atualizar a tela em tempo real, sem recarregar a página;
  • Entender o papel de um broker de mensageria (introdução — será aprofundado no Módulo 06).

🧠 Por que WebSocket para IoT?

Na Semana 19 usamos polling: o cliente pergunta "tem novidade?" de tempos em tempos. Funciona, mas gasta banda e sempre tem atraso (o tempo entre uma pergunta e outra).

O WebSocket abre uma conexão persistente e bidirecional entre cliente e servidor: depois do "aperto de mão" inicial (handshake), os dois lados podem enviar mensagens a qualquer momento, sem precisar abrir uma nova requisição HTTP a cada vez. Isso é exatamente o que sensores IoT precisam: assim que o ESP32 publica uma nova leitura, todos os painéis conectados recebem o dado imediatamente.

Esse padrão de "muitos dispositivos publicando e muitos clientes recebendo" é a essência de sistemas distribuídos com brokers de mensageria (MQTT, RabbitMQ, Kafka — que vamos estudar em detalhe no Módulo 06, Semanas 28–32). Hoje construímos uma versão simplificada com WebSocket puro para entender o conceito na prática antes de usar ferramentas prontas.

🛠️ Passo a Passo — Servidor WebSocket + Cliente React

1 Crie a pasta do servidor (fora do projeto React)

Vamos ter dois projetos rodando ao mesmo tempo: o servidor (Node.js) e o front-end React da Semana 18/19. Crie uma pasta irmã:

mkdir servidor-sensores
cd servidor-sensores
npm init -y
npm install ws

ws é a biblioteca mais usada para WebSocket em Node.js.

2 Escreva o servidor que simula um sensor

Crie servidor.js:

const { WebSocketServer } = require('ws');

const wss = new WebSocketServer({ port: 8080 });
console.log('Servidor WebSocket rodando em ws://localhost:8080');

wss.on('connection', (socket) => {
  console.log('Novo cliente conectado. Total:', wss.clients.size);

  const intervalo = setInterval(() => {
    const leitura = {
      sensor: 'temperatura',
      valor: (20 + Math.random() * 10).toFixed(1),
      timestamp: new Date().toISOString(),
    };
    socket.send(JSON.stringify(leitura));
  }, 2000);

  socket.on('close', () => {
    clearInterval(intervalo);
    console.log('Cliente desconectado');
  });
});

Rode em um terminal separado (deixe ele aberto):

node servidor.js

Esse servidor simula exatamente o que um ESP32 real faria: a cada 2 segundos, "publica" uma nova leitura para quem estiver escutando.

3 Teste o servidor com um cliente de linha de comando (opcional)

Antes de mexer no React, você pode testar rapidamente com a ferramenta wscat:

npm install -g wscat
wscat -c ws://localhost:8080

Você deve ver mensagens JSON chegando a cada 2 segundos direto no terminal.

4 Conectando o React ao WebSocket

No projeto dashboard-iot (o mesmo das semanas anteriores), crie src/useWebSocket.js:

import { useState, useEffect, useRef } from 'react';

function useWebSocket(url) {
  const [ultimaLeitura, setUltimaLeitura] = useState(null);
  const [conectado, setConectado] = useState(false);
  const socketRef = useRef(null);

  useEffect(() => {
    const socket = new WebSocket(url);
    socketRef.current = socket;

    socket.onopen = () => setConectado(true);

    socket.onmessage = (evento) => {
      const dado = JSON.parse(evento.data);
      setUltimaLeitura(dado);
    };

    socket.onclose = () => setConectado(false);
    socket.onerror = (err) => console.error('Erro no WebSocket:', err);

    return () => socket.close(); // fecha a conexão ao desmontar o componente
  }, [url]);

  return { ultimaLeitura, conectado };
}

export default useWebSocket;
5 Exibindo o dado em tempo real

Crie src/SensorAoVivo.jsx:

import useWebSocket from './useWebSocket';

function SensorAoVivo() {
  const { ultimaLeitura, conectado } = useWebSocket('ws://localhost:8080');

  return (
    <div style={{ padding: 20, border: '1px solid #333', borderRadius: 10 }}>
      <p>Status: {conectado ? '🟢 conectado' : '🔴 desconectado'}</p>
      {ultimaLeitura ? (
        <>
          <h2>{ultimaLeitura.valor} °C</h2>
          <small>Atualizado em {new Date(ultimaLeitura.timestamp).toLocaleTimeString()}</small>
        </>
      ) : (
        <p>Aguardando primeira leitura...</p>
      )}
    </div>
  );
}

export default SensorAoVivo;

Com o servidor.js rodando em um terminal e npm run dev rodando em outro, abra o navegador: o valor da temperatura deve mudar sozinho a cada 2 segundos, sem nenhum fetch manual — o servidor é quem "empurra" o dado.

6 Mantendo um histórico de leituras

Um dashboard fica mais útil mostrando as últimas leituras, não só a atual. Ajuste o hook para acumular um histórico limitado:

const [historico, setHistorico] = useState([]);

socket.onmessage = (evento) => {
  const dado = JSON.parse(evento.data);
  setHistorico(anterior => [...anterior.slice(-19), dado]); // mantém só as últimas 20 leituras
};
Por que slice(-19)? Sem limitar o tamanho do array, um dashboard que fica ligado por horas acumularia milhares de itens em memória — outro cuidado importante de performance em aplicações de streaming de dados.
7 Reconexão automática (robustez)

Redes IoT caem. Adicione uma tentativa de reconexão simples:

socket.onclose = () => {
  setConectado(false);
  setTimeout(() => {
    // reexecuta o efeito criando uma nova conexão
  }, 3000);
};

Uma forma prática de implementar isso é guardar um contador de "tentativa" no estado e incluí-lo nas dependências do useEffect, forçando o efeito a rodar de novo após o timeout.

🧪 Checkpoint TDD

Testar WebSocket de verdade em unidade é complexo — a prática comum é criar um mock da classe WebSocket global e simular eventos onmessage manualmente, verificando se o estado do componente atualiza como esperado. Documente no README como você testaria isso (não é obrigatório implementar o mock completo esta semana).

📡 Sensor ao Vivo

Construa o par servidor WebSocket + cliente React funcionando localmente, com histórico de leituras.

📋 Instruções:

  1. Crie o servidor servidor.js simulando pelo menos 2 sensores diferentes (ex: temperatura e umidade), enviando leituras separadas a cada 1–3 segundos;
  2. Implemente o hook useWebSocket no React consumindo essas leituras;
  3. Exiba um histórico das últimas 10–20 leituras de cada sensor (pode ser uma lista simples, não precisa de gráfico ainda — isso vem na Semana 21);
  4. Mostre visualmente o status da conexão (conectado/desconectado);
  5. Implemente alguma forma de reconexão ou, no mínimo, uma mensagem clara de erro quando o servidor cai;
  6. Documente no README como rodar os dois projetos (servidor e front-end) juntos;
  7. Commit e push no mesmo repositório GitHub.
📦 Entregável: Repositório GitHub com os dois projetos (ou pastas servidor/ e frontend/) + vídeo curto (1–2 min) ou GIF mostrando os dados atualizando ao vivo.

✅ Critérios de Avaliação:

  • Servidor WebSocket funcionando com pelo menos 2 sensores simulados
  • Cliente React recebendo e exibindo dados em tempo real corretamente
  • Histórico de leituras implementado com limite de tamanho
  • Indicação clara do status da conexão
  • README com instruções claras de execução

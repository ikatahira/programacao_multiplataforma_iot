React.js — Componentes e Hooks

Monte todo o ambiente de desenvolvimento sem instalar nada, direto no navegador com StackBlitz, e aprenda JSX, props, useState e useEffect construindo os primeiros cards de sensores. Esta versão traz o passo a passo bem mais detalhado, com diagramas explicando cada conceito e checkpoints para você conferir se está no caminho certo.

🎯 Objetivos de Aprendizagem

  • Montar um ambiente de desenvolvimento React sem instalar nada no computador do laboratório;
  • Aprender a usar o StackBlitz, um "VS Code dentro do navegador" que roda Node.js de verdade;
  • Entender por que usamos React.js para aplicações web responsivas com dados em tempo real;
  • Criar componentes funcionais e entender a sintaxe JSX;
  • Entender como os dados fluem entre componentes através de props, e visualizar isso em um diagrama;
  • Usar os hooks useState e useEffect para controlar estado e efeitos colaterais, entendendo o ciclo completo (o que acontece antes, durante e depois de cada atualização);
  • Salvar o projeto no GitHub direto do navegador, sem usar comandos de git instalados localmente;
  • Escrever e rodar o primeiro teste automatizado do curso.
📖 Glossário desta semana — clique para expandir (23 termos)
StackBlitz
Site que roda um ambiente de programação completo (editor + terminal + Node.js) dentro do navegador, sem precisar instalar nada no computador.
WebContainer
A tecnologia por trás do StackBlitz: um "computador virtual" com Node.js rodando dentro da própria aba do navegador, usando WebAssembly.
Node.js
Um programa que permite rodar código JavaScript fora do navegador — é o "motor" que executa o servidor e as ferramentas de build (Vite, npm, etc).
npm
Node Package Manager — o "gerenciador de pacotes" do Node.js. Serve para instalar bibliotecas prontas (como React) digitando comandos no terminal.
Vite
Ferramenta que organiza, empacota e serve seu projeto React durante o desenvolvimento, com atualização automática no navegador.
React
Biblioteca JavaScript para construir interfaces (telas) organizadas em pequenas peças reutilizáveis chamadas componentes.
componente
Uma peça reutilizável de interface (um pedaço de tela) escrita como uma função JavaScript que retorna o que deve aparecer na página.
JSX
Uma extensão de sintaxe do JavaScript que permite escrever algo parecido com HTML dentro do código — é convertido em JavaScript puro por trás dos panos.
props
Abreviação de "properties" (propriedades) — são os dados que um componente recebe de fora, como parâmetros de uma função.
children
Uma prop especial e automática que representa o conteúdo colocado entre as tags de abertura e fechamento de um componente.
hook
Uma função especial do React (sempre começa com "use", como useState) que permite componentes de função usar recursos como estado e efeitos colaterais.
estado (state)
Um dado que pertence a um componente e que, quando muda, faz a tela se atualizar sozinha automaticamente.
useState
Hook do React que cria uma variável de estado: guarda um valor e fornece uma função para atualizá-lo.
re-renderização
O processo pelo qual o React roda de novo a função do componente para calcular a nova versão da tela, depois de um estado mudar.
useEffect
Hook do React que executa código em resposta a mudanças (ex: buscar dados, iniciar um temporizador) — os chamados "efeitos colaterais".
efeito colateral
Qualquer ação que um componente faz além de simplesmente desenhar a tela — como buscar dados na internet, ligar um temporizador ou mexer no armazenamento do navegador.
função de limpeza (cleanup)
Código que o useEffect executa antes de rodar de novo ou quando o componente é removido da tela, usado para "desligar" o que foi ligado (ex: parar um setInterval).
setInterval
Função nativa do JavaScript que repete uma ação de tempos em tempos (ex: a cada 2000 milissegundos = 2 segundos).
reconciliação (diffing)
Processo interno do React que compara a versão antiga e a nova da tela e atualiza no navegador só o que realmente mudou, usando a prop key para reconhecer itens em listas.
Hot Module Reload
Recurso do Vite que atualiza a página no navegador automaticamente assim que você salva uma alteração no código, sem precisar recarregar tudo.
Vitest
Ferramenta (test runner) usada para escrever e rodar testes automatizados no projeto, integrada nativamente ao Vite.
commit
Um "registro" de uma versão do seu código no Git/GitHub, com uma mensagem descrevendo o que mudou.
push
Ação de enviar seus commits salvos localmente para o repositório remoto no GitHub, tornando-os visíveis para quem tiver acesso ao repositório.
repositório
Uma pasta de projeto versionada e hospedada no GitHub, contendo todo o histórico de alterações do código.

6 Seu primeiro componente e o JSX

Digite (ou cole) isto em App.tsx — repare na primeira linha, // @ts-nocheck, que desliga a checagem de tipos do TypeScript nesta semana (explicado no passo 3):

// @ts-nocheck
function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <h1>Central de Sensores</h1>
      <p>Bem-vindo ao seu primeiro componente React!</p>
    </div>
  );
}

export default App;

Assim que você salva (o StackBlitz salva sozinho enquanto você digita graças ao Hot Module Reload — não existe "Ctrl+S obrigatório", mas pode usar mesmo assim), olhe o painel de Preview à direita: ele atualiza sozinho, mostrando o título "Central de Sensores" e o parágrafo abaixo. Repare que dentro do return() você escreve algo parecido com HTML dentro do JavaScript — isso é JSX.

Uma dúvida comum de quem está começando: "isso é HTML de verdade?" Não é. Por trás dos panos, uma ferramenta chamada Babel transforma cada "tag" JSX em uma chamada de função JavaScript. A linha <h1>Central de Sensores</h1> vira, na prática, algo como React.createElement('h1', null, 'Central de Sensores'). Você nunca precisa escrever isso manualmente — só precisa entender que é JavaScript por baixo, o que explica por que:

  • toda expressão JavaScript dentro do JSX vai entre chaves { } — ex: {2 + 2}, {nomeDaVariavel};
  • atributos usam nomes em camelCase (className em vez de class, onClick em vez de onclick);
  • você não pode usar a palavra reservada class nem for diretamente (por isso className e htmlFor).
Regra de ouro do JSX: todo componente deve retornar um único elemento pai (por isso a <div> envolvendo tudo), e atributos de estilo usam camelCase dentro de um objeto JS (style={{...}}) — repare nas chaves duplas: a de fora entra no modo JavaScript, a de dentro é o objeto de estilo em si.

Erros comuns nesta etapa:
  • "Adjacent JSX elements must be wrapped in an enclosing tag" → você esqueceu de colocar tudo dentro de uma única <div> (ou de um <>...</>, chamado Fragment);
  • Preview em branco e erro no terminal → confira se não falta fechar alguma tag ou alguma chave { };
  • Esqueceu o export default App; no final → o arquivo main.tsx não vai conseguir importar o componente.
Editou tudo certinho, mas o Preview continua mostrando a tela padrão do Vite ("Get started", "Count is 0")?

Isso não é erro no seu código — é o Preview que ficou "desconectado" e não aplicou a atualização, mesmo o terminal mostrando hmr update /src/App.tsx. É comum em redes de escola/corporativas, que às vezes atrapalham a conexão ao vivo (WebSocket) que o Vite usa para empurrar as mudanças. A correção é rápida:

  • Clique no ícone circular ⟳ (recarregar) que fica no topo do painel de Preview, ao lado do cadeado e da URL — é o suficiente na maioria das vezes;
  • Se não resolver, clique no ícone ↗ (abrir em nova aba) ao lado dele e dê um Ctrl+Shift+R na aba que abrir;
  • Se ainda assim persistir, clique no terminal, pressione Ctrl+C para parar o servidor e rode npm run dev de novo;
  • Em último caso, recarregue a aba inteira do StackBlitz (F5) — nada se perde, pois o projeto salva sozinho.
7 Criando um componente reutilizável — SensorCard

No painel FILES, clique com o botão direito na pasta src (não na raiz do projeto, nem em public) → New file → digite SensorCard.tsx e pressione Enter. Cole este conteúdo (não esqueça do // @ts-nocheck na primeira linha):

📁 O arquivo precisa ficar na mesma pasta que o App.tsx: repare, no painel FILES, que SensorCard.tsx deve aparecer dentro de src, no mesmo nível de App.tsx, App.css e main.tsx — e não dentro de src/assets, nem solto na raiz do projeto. É essa localização que faz o import SensorCard from './SensorCard' funcionar, porque ./ significa "a mesma pasta de quem está importando".
// @ts-nocheck
function SensorCard({ nome, valor, unidade }) {
  return (
    <div style={{
      border: '1px solid #333', borderRadius: 10,
      padding: 16, minWidth: 160, background: '#181d2f', color: '#fff'
    }}>
      <h3>{nome}</h3>
      <p style={{ fontSize: 28 }}>{valor} {unidade}</p>
    </div>
  );
}

export default SensorCard;

Este componente recebe props (nome, valor, unidade) — são os "parâmetros" de um componente, exatamente como parâmetros de uma função. A sintaxe { nome, valor, unidade } é destructuring: em vez de receber um único objeto props e escrever props.nome, props.valor etc., já "desempacotamos" cada propriedade direto no parâmetro da função. Agora use-o em App.tsx:

import SensorCard from './SensorCard';

function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24, display: 'flex', gap: 16 }}>
      <SensorCard nome="Temperatura" valor={24.5} unidade="°C" />
      <SensorCard nome="Umidade" valor={62} unidade="%" />
      <SensorCard nome="Luminosidade" valor={310} unidade="lux" />
    </div>
  );
}

export default App;

Repare que cada <SensorCard ... /> passa valores diferentes para o mesmo componente — é assim que reaproveitamos código em vez de copiar e colar três blocos de HTML parecidos.

Figura 2 — fluxo de dados por props: o componente-pai App passa valores diferentes para três instâncias do mesmo componente-filho SensorCard. Props sempre viajam de cima para baixo (pai → filho), nunca ao contrário.

✅ Como saber que deu certo: o Preview deve mostrar três cartões escuros lado a lado, cada um com um título diferente (Temperatura, Umidade, Luminosidade) e um número grande abaixo.
Erros comuns nesta etapa:
  • "nome is not defined" ou similar → esqueceu de colocar { nome, valor, unidade } entre parênteses na declaração da função SensorCard;
  • Cartões aparecem empilhados um embaixo do outro → confira se o <div> do App.tsx realmente tem display: 'flex' no style;
  • Erro "Cannot find module './SensorCard'" → o arquivo precisa se chamar exatamente SensorCard.tsx e estar dentro da pasta src, no mesmo nível de App.tsx.
8 Estado com useState

Sensores mudam de valor. Para a tela reagir a mudanças, usamos o hook useState. Edite App.tsx (mantendo o // @ts-nocheck na primeira linha):

// @ts-nocheck
import { useState } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  function atualizarTemperatura() {
    const novoValor = (20 + Math.random() * 10).toFixed(1);
    setTemperatura(novoValor);
  }

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
      <button onClick={atualizarTemperatura}>Simular nova leitura</button>
    </div>
  );
}

export default App;

useState(24.5) devolve dois itens: o valor atual do estado (temperatura) e uma função para atualizá-lo (setTemperatura). O número 24.5 entre parênteses é o valor inicial, usado apenas na primeira renderização. Sempre que você chama setTemperatura(...), o React re-renderiza (redesenha) o componente com o novo valor. Clique no botão no painel de Preview e veja o número mudar.

Figura 3 — toda vez que você chama a função "setter" (setTemperatura), o React não muda a tela na hora: ele agenda uma nova execução do componente, calcula a nova versão da interface e só então atualiza o navegador. É por isso que a variável de estado nunca deve ser alterada diretamente (ex: temperatura = 30 não funciona).

✅ Como saber que deu certo: a cada clique no botão "Simular nova leitura", o número dentro do cartão de Temperatura muda para um valor aleatório entre 20.0 e 30.0 — por exemplo, de 24.5 °C para algo como 20.3 °C. No terminal, você também deve ver linhas hmr update /src/App.tsx confirmando que o arquivo foi salvo e recarregado.
Erro comum: tentar mudar o estado diretamente com temperatura = novoValor em vez de setTemperatura(novoValor). Isso não causa erro no console, mas também não atualiza a tela — o React só percebe mudanças quando você usa a função retornada pelo useState.
9 Efeitos colaterais com useEffect — leitura automática

Em vez de depender de um clique, vamos simular um sensor que envia uma leitura nova a cada 2 segundos. Continue em App.tsx:

// @ts-nocheck
import { useState, useEffect } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  useEffect(() => {
    const intervalo = setInterval(() => {
      const novoValor = (20 + Math.random() * 10).toFixed(1);
      setTemperatura(novoValor);
    }, 2000);

    return () => clearInterval(intervalo); // limpeza ao desmontar o componente
  }, []); // [] = executa só uma vez, quando o componente monta

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
    </div>
  );
}

export default App;

Repare nos três pedaços do useEffect: a função que roda o efeito (liga o setInterval), a função de retorno (a limpeza, que desliga o setInterval) e o array de dependências [] no final, que controla quando o efeito roda de novo.

  • [] (array vazio) → o efeito roda uma única vez, quando o componente aparece na tela pela primeira vez (chamado de "montar"/mount);
  • [temperatura] → o efeito roda de novo toda vez que a variável temperatura mudar;
  • sem array nenhum → o efeito roda depois de toda renderização (raramente é o que você quer).

Figura 4 — ciclo de vida do efeito: ele liga um timer quando o componente aparece e o desliga quando o componente desaparece. Cada "tick" do setInterval chama setTemperatura, disparando o ciclo de re-renderização visto na Figura 3.

✅ Como saber que deu certo: sem clicar em nada, o número de temperatura no Preview muda sozinho a cada 2 segundos, indefinidamente — por exemplo, de 21.3 °C para 26.2 °C alguns segundos depois, e assim por diante. Repare que não existe mais o botão "Simular nova leitura": o cartão agora atualiza sozinho, sem nenhuma ação sua. No terminal, cada troca de código gera uma nova linha hmr update /src/App.tsx — mas as mudanças de valor do sensor em si acontecem só na tela, sem gerar linhas novas no terminal (elas são o setInterval rodando dentro do próprio navegador).
Atenção: sempre que usar setInterval dentro de useEffect, devolva uma função de limpeza (return () => clearInterval(...)). Sem isso, cada atualização do componente cria um novo intervalo "fantasma" rodando em paralelo — depois de alguns minutos você teria dezenas de intervalos simultâneos, deixando a página cada vez mais lenta.
10 Lista de sensores com .map()

Até agora criamos um cartão por vez, copiando e colando <SensorCard />. Isso não escala: se você tiver 20 sensores, não vai escrever 20 linhas repetidas. A solução é guardar os sensores em um array e usar .map() para transformar cada item do array em um componente.

⚠️ Este passo troca o arquivo inteiro: diferente dos passos anteriores, o código abaixo não é um "trecho para colar no meio" — é o App.tsx completo. Selecione tudo (Ctrl+A) dentro do editor e substitua pelo código a seguir. Ele já une o .map() com o useEffect automático do passo 9, para os três sensores atualizarem sozinhos ao mesmo tempo.
// @ts-nocheck
import { useState, useEffect } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [sensores, setSensores] = useState([
    { id: 1, nome: 'Temperatura',  valor: 24.5, unidade: '°C'  },
    { id: 2, nome: 'Umidade',      valor: 60,   unidade: '%'   },
    { id: 3, nome: 'Luminosidade', valor: 300,  unidade: 'lux' },
  ]);

  useEffect(() => {
    const intervalo = setInterval(() => {
      setSensores(atuais =>
        atuais.map(s => ({
          ...s,
          valor: (s.valor * (0.9 + Math.random() * 0.2)).toFixed(1),
        }))
      );
    }, 2000);

    return () => clearInterval(intervalo); // limpeza ao desmontar o componente
  }, []); // [] = liga o intervalo só uma vez, quando o componente monta

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24, display: 'flex', gap: 16 }}>
      {sensores.map(s => (
        <SensorCard key={s.id} nome={s.nome} valor={s.valor} unidade={s.unidade} />
      ))}
    </div>
  );
}

export default App;

Repare no { ...s, valor: ... } dentro do .map(): o ...s ("spread") copia todas as propriedades do sensor original (id, nome, unidade) e, na sequência, sobrescrevemos só o valor com um número novo. Isso evita reescrever manualmente cada campo — só o que muda é recalculado.

O atributo key é obrigatório em listas — ele não aparece na tela, mas ajuda o React a identificar de forma única cada item durante a reconciliação: assim, quando um sensor mudar de valor, o React sabe exatamente qual cartão redesenhar, sem precisar refazer a lista inteira do zero. Use sempre um identificador estável (como um id), nunca o índice da posição no array quando a lista pode ser reordenada ou ter itens removidos.

✅ Como saber que deu certo: o Preview mostra os três cartões lado a lado (Temperatura, Umidade, Luminosidade), e os três valores mudam sozinhos, ao mesmo tempo, a cada 2 segundos — sem nenhum botão na tela. Por exemplo, em um instante você vê 24.5 °C · 58.8 % · 367.1 lux, e alguns segundos depois os três já mudaram juntos para algo como 29.8 °C · 67.6 % · 377.4 lux. Se só um cartão estiver mudando (ou nenhum), revise se o setSensores está usando .map() para atualizar todos os itens do array, e não só um deles.
Erros comuns nesta etapa:
  • "Warning: Each child in a list should have a unique key prop" no console → falta o atributo key em algum item gerado pelo .map();
  • Usar key={'{index}'} (a posição no array) funciona sem warnings, mas pode causar bugs sutis de reordenação — prefira sempre um id real do dado;
  • Se colar só o trecho do useState/.map() dentro do código antigo do passo 9 (que ainda tinha o botão), vai sobrar código duplicado ou quebrado — por isso a orientação é apagar tudo e colar o arquivo completo acima.

12 Rodando testes com Vitest (no mesmo terminal do navegador)

Clique na aba Terminal na parte inferior do StackBlitz (é um terminal real, dentro do WebContainer) e digite o comando abaixo, que usa o npm para instalar o Vitest e bibliotecas auxiliares de teste:

npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom

A instalação pode levar 20-40 segundos (o WebContainer está baixando pacotes reais do npm). Enquanto isso não termina, aparece um cursor piscando no terminal — não digite nada até ele voltar ao prompt normal ($).

Crie o arquivo src/SensorCard.test.tsx (mesmo processo do passo 7: botão direito em src → New file):

// @ts-nocheck
import { render, screen } from '@testing-library/react';
import SensorCard from './SensorCard';

test('mostra o nome do sensor', () => {
  render(<SensorCard nome="Temperatura" valor={25} unidade="°C" />);
  expect(screen.getByText('Temperatura')).toBeInTheDocument();
});

Em palavras simples, o teste faz três coisas: renderiza o componente SensorCard como se ele estivesse em uma tela real, procura na tela renderizada um texto chamado "Temperatura" e depois verifica (assert) que esse texto realmente apareceu. Se alguém mudar o componente e o nome do sensor sumir da tela por engano, este teste vai falhar e avisar antes que o erro chegue ao usuário final.

No terminal, rode:

npx vitest run

Vamos aprofundar TDD no Módulo 08 (Semanas 37–39), mas escrever este primeiro teste agora já cria o hábito.

✅ Como saber que deu certo: o terminal mostra uma linha verde com "✓ mostra o nome do sensor" e, ao final, um resumo do tipo "1 passed".
Erro comum: "test is not defined" — normalmente significa que o Vitest ainda não terminou de instalar, ou que o arquivo de teste não está na pasta src. Confira também se o nome do arquivo termina exatamente em .test.tsx.

📋 Instruções:

  1. Use o projeto dashboard-iot-isw044 criado no StackBlitz seguindo o passo a passo acima;
  2. Crie um componente SensorCard reutilizável, recebendo nome, valor e unidade via props;
  3. Guarde os sensores em um array de estado (useState) com pelo menos 4 sensores diferentes (ex: temperatura, umidade, luminosidade, nível de CO₂);

React.js — Componentes e Hooks

Monte o ambiente, aprenda JSX, props, useState e useEffect construindo os primeiros cards de sensores que serão a base do dashboard IoT do módulo.

🎯 Objetivos de Aprendizagem

  • Entender por que usamos React.js para construir aplicações web responsivas dentro da ementa de Desenvolvimento Web Moderno;
  • Instalar o ambiente de desenvolvimento (Node.js, npm, Vite) do zero;
  • Criar componentes funcionais e entender a sintaxe JSX;
  • Usar os hooks useState e useEffect para controlar estado e efeitos colaterais;
  • Construir uma primeira "central de sensores" simulada — base para o dashboard IoT das próximas semanas;
  • Versionar o projeto com Git/GitHub desde o primeiro commit.

🧠 Por que React neste módulo?

A ementa da disciplina pede aplicações web responsivas capazes de exibir, em tempo real, dados vindos de sensores IoT (Arduino/ESP32). Fazer isso só com HTML/CSS/JS puro é possível, mas fica difícil de manter quando a tela precisa atualizar sozinha a cada novo dado — exatamente o que um sensor faz o tempo todo.

O React resolve isso organizando a interface em componentes (peças reutilizáveis de UI) que re-renderizam automaticamente sempre que o estado (state) muda. É a base que vamos usar nas Semanas 19 a 22 para consumir APIs REST, receber dados via WebSocket e montar o dashboard IoT final.

🛠️ Passo a Passo — Monte o ambiente e o primeiro projeto

Siga os passos na ordem. Todos os comandos abaixo funcionam em Windows, Linux ou Mac (terminal / PowerShell / Prompt de Comando). Você só precisa de um computador com internet — nenhuma placa física é necessária nesta semana.

Abra o terminal e digite:

node -v
npm -v

Se aparecer um número de versão (ex: v20.11.0), está tudo certo. Se der erro de "comando não encontrado", baixe o instalador em nodejs.org (versão LTS), instale e reinicie o terminal.

cd dashboard-iot
npm install

O terminal vai mostrar um endereço como http://localhost:5173. Abra no navegador — você deve ver a tela padrão do Vite + React girando o logo.

4 Seu primeiro componente e o JSX

Cole isto em App.jsx:

function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <h1>Central de Sensores</h1>
      <p>Bem-vindo ao seu primeiro componente React!</p>
    </div>
  );
}

export default App;

Salve e olhe o navegador (ele atualiza sozinho, isso se chama Hot Module Reload). Repare que dentro do return() você escreve algo parecido com HTML dentro do JavaScript — isso é JSX. Por baixo dos panos, o JSX vira chamadas de função (React.createElement), mas escrever assim é muito mais legível.

Regra de ouro do JSX: todo componente deve retornar um único elemento pai (por isso a <div> envolvendo tudo), e atributos de estilo usam camelCase dentro de um objeto JS (style={{...}}).

5 Criando um componente reutilizável — SensorCard

Crie o arquivo src/SensorCard.jsx:

function SensorCard({ nome, valor, unidade }) {
  return (
    <div style={{
      border: '1px solid #333', borderRadius: 10,
      padding: 16, minWidth: 160, background: '#181d2f', color: '#fff'
    }}>
      <h3>{nome}</h3>
      <p style={{ fontSize: 28 }}>{valor} {unidade}</p>
    </div>
  );
}

export default SensorCard;

Este componente recebe props (nome, valor, unidade) — são os "parâmetros" de um componente, exatamente como parâmetros de uma função. Agora use-o em App.jsx:

import SensorCard from './SensorCard';

function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24, display: 'flex', gap: 16 }}>
      <SensorCard nome="Temperatura" valor={24.5} unidade="°C" />
      <SensorCard nome="Umidade" valor={62} unidade="%" />
      <SensorCard nome="Luminosidade" valor={310} unidade="lux" />
    </div>
  );
}

export default App;

Você acabou de reaproveitar o mesmo componente três vezes com dados diferentes — é exatamente assim que, mais adiante, cada sensor real do ESP32 vai virar um card na tela.

6 Estado com useState

Sensores mudam de valor. Para a tela reagir a mudanças, usamos o hook useState. Edite App.jsx:

import { useState } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  function atualizarTemperatura() {
    const novoValor = (20 + Math.random() * 10).toFixed(1);
    setTemperatura(novoValor);
  }

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
      <button onClick={atualizarTemperatura}>Simular nova leitura</button>
    </div>
  );
}

export default App;

useState(24.5) devolve dois itens: o valor atual (temperatura) e uma função para atualizá-lo (setTemperatura). Sempre que você chama setTemperatura(...), o React re-renderiza o componente com o novo valor — automaticamente, sem manipular o DOM na mão.

7 Efeitos colaterais com useEffect — leitura automática

Em vez de depender de um clique, vamos simular um sensor que envia uma leitura nova a cada 2 segundos — o comportamento real de um ESP32 publicando dados periodicamente:

import { useState, useEffect } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  useEffect(() => {
    const intervalo = setInterval(() => {
      const novoValor = (20 + Math.random() * 10).toFixed(1);
      setTemperatura(novoValor);
    }, 2000);

    return () => clearInterval(intervalo); // limpeza ao desmontar o componente
  }, []); // [] = executa só uma vez, quando o componente monta

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
    </div>
  );
}

export default App;
Atenção: sempre que usar setInterval/setTimeout/assinaturas dentro de useEffect, devolva uma função de limpeza (return () => clearInterval(...)). Sem isso, cada vez que o componente atualizar você cria um novo intervalo "fantasma" rodando em paralelo — um bug clássico em dashboards em tempo real.
8 Lista de sensores com .map()

Na prática você terá vários sensores. Em vez de repetir <SensorCard /> manualmente, guarde-os em um array de estado e renderize com .map():

const [sensores, setSensores] = useState([
  { id: 1, nome: 'Temperatura', valor: 24.5, unidade: '°C' },
  { id: 2, nome: 'Umidade',     valor: 60,   unidade: '%'  },
  { id: 3, nome: 'Luminosidade',valor: 300,  unidade: 'lux'},
]);

// ...dentro do return:
<div style={{ display: 'flex', gap: 16 }}>
  {sensores.map(s => (
    <SensorCard key={s.id} nome={s.nome} valor={s.valor} unidade={s.unidade} />
  ))}
</div>

O atributo key é obrigatório em listas — ajuda o React a saber qual item mudou sem precisar redesenhar a lista inteira.

🧪 Checkpoint TDD (introdução)

A ementa pede Desenvolvimento Dirigido a Testes. Você não precisa dominar TDD ainda, mas já pode instalar o Vitest (test runner que integra nativamente com Vite) para começar a se acostumar: 
npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom

Crie src/SensorCard.test.jsx com um teste simples que verifica se o nome do sensor aparece na tela:

import { render, screen } from '@testing-library/react';
import SensorCard from './SensorCard';

test('mostra o nome do sensor', () => {
  render(<SensorCard nome="Temperatura" valor={25} unidade="°C" />);
  expect(screen.getByText('Temperatura')).toBeInTheDocument();
});

Rode com npx vitest. Vamos aprofundar TDD no Módulo 08 (Semanas 37–39), mas escrever este primeiro teste agora cria o hábito.

📋 Instruções:

  1. Crie o projeto Vite + React seguindo o passo a passo acima (ou continue o projeto já criado);
  2. Crie um componente SensorCard reutilizável, recebendo nome, valor e unidade via props;
  3. Guarde os sensores em um array de estado (useState) com pelo menos 4 sensores diferentes (ex: temperatura, umidade, luminosidade, nível de CO₂);

  7. Escreva pelo menos 1 teste com Vitest para um dos componentes;
  8. Faça commit e push para um repositório público no GitHub com um README.md explicando o projeto.

  • Uso correto de componentes, props, useState e useEffect

React.js — Componentes e Hooks

Monte todo o ambiente de desenvolvimento sem instalar nada, direto no navegador com StackBlitz, e aprenda JSX, props, useState e useEffect construindo os primeiros cards de sensores.

🎯 Objetivos de Aprendizagem

  • Montar um ambiente de desenvolvimento React sem instalar nada no computador do laboratório;
  • Aprender a usar o StackBlitz, um "VS Code dentro do navegador" que roda Node.js de verdade;
  • Entender por que usamos React.js para aplicações web responsivas com dados em tempo real;
  • Criar componentes funcionais e entender a sintaxe JSX;
  • Usar os hooks useState e useEffect para controlar estado e efeitos colaterais;
  • Salvar o projeto no GitHub direto do navegador, sem usar comandos de git instalados localmente.
📖 Glossário desta semana — clique para expandir (20 termos)
StackBlitz
Site que roda um ambiente de programação completo (editor + terminal + Node.js) dentro do navegador, sem precisar instalar nada no computador.
WebContainer
A tecnologia por trás do StackBlitz: um "computador virtual" com Node.js rodando dentro da própria aba do navegador, usando WebAssembly.
Node.js
Um programa que permite rodar código JavaScript fora do navegador — é o "motor" que executa o servidor e as ferramentas de build (Vite, npm, etc).
npm
Node Package Manager — o "gerenciador de pacotes" do Node.js. Serve para instalar bibliotecas prontas (como React) digitando comandos no terminal.
Vite
Ferramenta que organiza, empacota e serve seu projeto React durante o desenvolvimento, com atualização automática no navegador.
React
Biblioteca JavaScript para construir interfaces (telas) organizadas em pequenas peças reutilizáveis chamadas componentes.
componente
Uma peça reutilizável de interface (um pedaço de tela) escrita como uma função JavaScript que retorna o que deve aparecer na página.
JSX
Uma extensão de sintaxe do JavaScript que permite escrever algo parecido com HTML dentro do código — é convertido em JavaScript puro por trás dos panos.
props
Abreviação de "properties" (propriedades) — são os dados que um componente recebe de fora, como parâmetros de uma função.
hook
Uma função especial do React (sempre começa com "use", como useState) que permite componentes de função usar recursos como estado e efeitos colaterais.
estado (state)
Um dado que pertence a um componente e que, quando muda, faz a tela se atualizar sozinha automaticamente.
useState
Hook do React que cria uma variável de estado: guarda um valor e fornece uma função para atualizá-lo.
useEffect
Hook do React que executa código em resposta a mudanças (ex: buscar dados, iniciar um temporizador) — os chamados "efeitos colaterais".
efeito colateral
Qualquer ação que um componente faz além de simplesmente desenhar a tela — como buscar dados na internet, ligar um temporizador ou mexer no armazenamento do navegador.
setInterval
Função nativa do JavaScript que repete uma ação de tempos em tempos (ex: a cada 2000 milissegundos = 2 segundos).
Hot Module Reload
Recurso do Vite que atualiza a página no navegador automaticamente assim que você salva uma alteração no código, sem precisar recarregar tudo.
Vitest
Ferramenta (test runner) usada para escrever e rodar testes automatizados no projeto, integrada nativamente ao Vite.
commit
Um "registro" de uma versão do seu código no Git/GitHub, com uma mensagem descrevendo o que mudou.
push
Ação de enviar seus commits salvos localmente para o repositório remoto no GitHub, tornando-os visíveis para quem tiver acesso ao repositório.
repositório
Uma pasta de projeto versionada e hospedada no GitHub, contendo todo o histórico de alterações do código.

🖥️ Ambiente de Desenvolvimento — sem instalar absolutamente nada

Nos laboratórios da FATEC os computadores rodam Windows 11 e você não tem permissão para instalar programas (nem o Node.js, nem o VS Code, nem o Git). Isso não é um problema: vamos usar o StackBlitz, um site que roda um ambiente Node.js completo dentro do próprio navegador, usando uma tecnologia chamada WebContainers. Na prática, para você, ele se comporta exatamente como o VS Code + terminal + Node instalados — só que 100% dentro de uma aba do Edge ou Chrome, sem precisar de permissão de administrador.

Funciona em qualquer computador: como nada é instalado localmente, você pode sair do laboratório, chegar em outro computador na próxima semana (ou em casa) e continuar exatamente de onde parou — desde que entre com a mesma conta.

O GitHub é onde seu código fica salvo permanentemente — e é exigido pela ementa da disciplina (controle de versionamento). Abra o navegador e acesse:

https://github.com/join

Preencha e-mail, senha e um nome de usuário (ex: seunome-fatec). Confirme o e-mail que o GitHub envia. Isso leva menos de 3 minutos e você só precisa fazer isso uma única vez em todo o curso.

2 Abra o StackBlitz e entre com sua conta GitHub

No navegador (Edge já vem instalado no Windows 11; se preferir, o Chrome também funciona), acesse:

https://stackblitz.com

No canto superior direito, clique em Sign in e escolha Continue with GitHub. Autorize o acesso na tela que o GitHub abrir. Pronto — sua conta StackBlitz agora está ligada à sua conta GitHub, e qualquer projeto que você criar pode ser salvo lá.

Site bloqueado no laboratório? Se stackblitz.com estiver bloqueado pelo firewall da escola, avise o professor/técnico. Como alternativa equivalente (mesmo fluxo, mesma ideia de "IDE sem instalação"), você pode usar replit.com ou codesandbox.io — os passos de criar projeto React e usar o terminal são muito parecidos.

Ainda na página inicial do StackBlitz, clique no botão "Create new" (ou "+ New Project" / "New"). Na galeria de templates que abrir, procure e clique no card "React" (ele já vem configurado com Vite, a ferramenta que empacota o projeto — não é necessário escolher nada a mais).

Espere alguns segundos: na primeira vez, o StackBlitz está baixando e montando um Node.js completo dentro da própria aba do navegador. Quando terminar, você verá três áreas principais na tela:

  • Esquerda: explorador de arquivos (igual ao do VS Code);
  • Centro: o editor de código (também é o mesmo "motor" do VS Code, então os atalhos de teclado são os mesmos);
  • Direita: a pré-visualização (Preview) do site rodando ao vivo, atualizando sozinha a cada alteração;
  • Aba "Terminal" na parte de baixo/lateral: um terminal de verdade, onde vamos digitar comandos npm ao longo do curso.

Clique no nome do projeto no topo da página (geralmente algo como "vitejs-vite-xxxxxx") e troque para dashboard-iot-isw044. Isso ajuda a identificar o projeto quando você voltar nas próximas semanas.

6 Seu primeiro componente e o JSX

Digite (ou cole) isto em App.jsx:

function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <h1>Central de Sensores</h1>
      <p>Bem-vindo ao seu primeiro componente React!</p>
    </div>
  );
}

export default App;

Assim que você salva (o StackBlitz salva sozinho enquanto você digita graças ao Hot Module Reload — não existe "Ctrl+S obrigatório", mas pode usar mesmo assim), olhe o painel de Preview à direita: ele atualiza sozinho. Repare que dentro do return() você escreve algo parecido com HTML dentro do JavaScript — isso é JSX.

Regra de ouro do JSX: todo componente deve retornar um único elemento pai (por isso a <div> envolvendo tudo), e atributos de estilo usam camelCase dentro de um objeto JS (style={{...}}).
7 Criando um componente reutilizável — SensorCard

No explorador de arquivos, clique com o botão direito na pasta src → New file → digite SensorCard.jsx e pressione Enter. Cole este conteúdo:

function SensorCard({ nome, valor, unidade }) {
  return (
    <div style={{
      border: '1px solid #333', borderRadius: 10,
      padding: 16, minWidth: 160, background: '#181d2f', color: '#fff'
    }}>
      <h3>{nome}</h3>
      <p style={{ fontSize: 28 }}>{valor} {unidade}</p>
    </div>
  );
}

export default SensorCard;

Este componente recebe props (nome, valor, unidade) — são os "parâmetros" de um componente, exatamente como parâmetros de uma função. Agora use-o em App.jsx:

import SensorCard from './SensorCard';

function App() {
  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24, display: 'flex', gap: 16 }}>
      <SensorCard nome="Temperatura" valor={24.5} unidade="°C" />
      <SensorCard nome="Umidade" valor={62} unidade="%" />
      <SensorCard nome="Luminosidade" valor={310} unidade="lux" />
    </div>
  );
}

export default App;
8 Estado com useState

Sensores mudam de valor. Para a tela reagir a mudanças, usamos o hook useState. Edite App.jsx:

import { useState } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  function atualizarTemperatura() {
    const novoValor = (20 + Math.random() * 10).toFixed(1);
    setTemperatura(novoValor);
  }

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
      <button onClick={atualizarTemperatura}>Simular nova leitura</button>
    </div>
  );
}

export default App;

useState(24.5) devolve dois itens: o valor atual do estado (temperatura) e uma função para atualizá-lo (setTemperatura). Sempre que você chama setTemperatura(...), o React re-renderiza (redesenha) o componente com o novo valor. Clique no botão no painel de Preview e veja o número mudar.

9 Efeitos colaterais com useEffect — leitura automática

Em vez de depender de um clique, vamos simular um sensor que envia uma leitura nova a cada 2 segundos:

import { useState, useEffect } from 'react';
import SensorCard from './SensorCard';

function App() {
  const [temperatura, setTemperatura] = useState(24.5);

  useEffect(() => {
    const intervalo = setInterval(() => {
      const novoValor = (20 + Math.random() * 10).toFixed(1);
      setTemperatura(novoValor);
    }, 2000);

    return () => clearInterval(intervalo); // limpeza ao desmontar o componente
  }, []); // [] = executa só uma vez, quando o componente monta

  return (
    <div style={{ fontFamily: 'sans-serif', padding: 24 }}>
      <SensorCard nome="Temperatura" valor={temperatura} unidade="°C" />
    </div>
  );
}

export default App;
Atenção: sempre que usar setInterval dentro de useEffect, devolva uma função de limpeza (return () => clearInterval(...)). Sem isso, cada atualização do componente cria um novo intervalo "fantasma" rodando em paralelo.
10 Lista de sensores com .map()
const [sensores, setSensores] = useState([
  { id: 1, nome: 'Temperatura', valor: 24.5, unidade: '°C' },
  { id: 2, nome: 'Umidade',     valor: 60,   unidade: '%'  },
  { id: 3, nome: 'Luminosidade',valor: 300,  unidade: 'lux'},
]);

// ...dentro do return:
<div style={{ display: 'flex', gap: 16 }}>
  {sensores.map(s => (
    <SensorCard key={s.id} nome={s.nome} valor={s.valor} unidade={s.unidade} />
  ))}
</div>

O atributo key é obrigatório em listas — ajuda o React a saber qual item mudou sem redesenhar a lista inteira.

11 Salvando o projeto no GitHub (sem usar git no terminal)

Na barra superior do StackBlitz, procure o ícone do GitHub (perto do nome do projeto) e clique nele — a opção pode aparecer como "Connect Repository" ou "Export to GitHub". Escolha criar um novo repositório, dê o nome dashboard-iot-isw044 e confirme. O StackBlitz envia todos os arquivos automaticamente para o seu GitHub — nenhum comando git é digitado.

A partir de agora, sempre que quiser salvar uma nova versão do trabalho, clique novamente nesse mesmo ícone e use a opção de commit/push disponível ali, escrevendo uma mensagem curta descrevendo o que mudou (ex: "adiciona SensorCard e useEffect").

Por que isso substitui o Git tradicional? O comando git por trás continua existindo — só que quem digita os comandos é o próprio StackBlitz, através da API do GitHub. O resultado no seu repositório é idêntico ao que você teria rodando git add / commit / push localmente.
12 Rodando testes com Vitest (no mesmo terminal do navegador)

Clique na aba Terminal na parte inferior do StackBlitz (é um terminal real, dentro do WebContainer) e digite o comando abaixo, que usa o npm para instalar o Vitest e bibliotecas auxiliares de teste:

npm install -D vitest @testing-library/react @testing-library/jest-dom jsdom

Crie o arquivo src/SensorCard.test.jsx (mesmo processo do passo 7: botão direito em src → New file):

import { render, screen } from '@testing-library/react';
import SensorCard from './SensorCard';

test('mostra o nome do sensor', () => {
  render(<SensorCard nome="Temperatura" valor={25} unidade="°C" />);
  expect(screen.getByText('Temperatura')).toBeInTheDocument();
});

No terminal, rode:

npx vitest run

Vamos aprofundar TDD no Módulo 08 (Semanas 37–39), mas escrever este primeiro teste agora já cria o hábito.

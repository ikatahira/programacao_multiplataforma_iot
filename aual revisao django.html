Django

Framework web "batteries included" em Python

Pré-requisitos

Python e pip instalados

Verifique as versões antes de instalar:

python --version
pip --version
Passo a passo

Instalação completa

  • Criar e ativar um ambiente virtual

    Isola as dependências do projeto do sistema global.

    # Criar o venv
python -m venv venv

# Ativar — Linux / macOS
source venv/bin/activate

# Ativar — Windows
venv\Scripts\activate
  • Instalar o Django 
    pip install django

# Versão específica (opcional)
pip install django==5.0
  • Confirmar a instalação 
    python -m django --version
  • Criar um novo projeto 
    django-admin startproject meu_projeto .
# O ponto final cria na pasta atual
  • Rodar o servidor de desenvolvimento 
    python manage.py runserver
# Acesse: http://127.0.0.1:8000
Salvar dependências
pip freeze > requirements.txt

# Reinstalar em outro ambiente
pip install -r requirements.txt
Criar uma app
python manage.py startapp blog

# Aplicar migrações
python manage.py migrate
💡 Dica: Sempre ative o ambiente virtual antes de instalar pacotes. Quando ativo, o terminal mostra (venv) no início da linha.
⚗️

Flask

Microframework minimalista e flexível em Python

Passo a passo

Instalação e primeiro app

  • Ambiente virtual (igual ao Django) 
    python -m venv venv
source venv/bin/activate  # Linux/macOS
  • Instalar o Flask 
    pip install flask
  • Criar o arquivo principal app.py 
    from flask import Flask

app = Flask(__name__)

@app.route('/')
def index():
    return 'Olá, Mundo!'

if __name__ == '__main__':
    app.run(debug=True)
  • Rodar a aplicação 
    python app.py
# Acesse: http://127.0.0.1:5000

# Ou via variável de ambiente:
flask --app app run --debug
Django vs Flask

Quando usar cada um?

🐍 Django

Projetos grandes · Admin pronto · ORM built-in · Autenticação embutida · Estrutura definida

⚗️ Flask

APIs simples · Projetos pequenos · Liberdade total · Aprendizado · Microservices

⚠️ Modo debug: Use debug=True apenas em desenvolvimento. Em produção, use um servidor WSGI como Gunicorn ou uWSGI.

Git

Controle de versão: add → commit → push

Fluxo de trabalho
Seus arquivos
Working Dir
→
git add
Stage
→
git commit
Repo local
→
git push
Remoto
  • git add .

    Adiciona todos os arquivos novos e modificados à área de staging (preparação para o commit).

    git add .             # tudo de uma vez
git add arquivo.py    # arquivo específico
git add pasta/        # pasta inteira
git status           # veja o que foi adicionado
  • git commit -m "mensagem"

    Cria um snapshot permanente dos arquivos em stage. A mensagem deve ser clara e descrever o que foi feito.

    git commit -m "feat: adiciona página de login"
git commit -m "fix: corrige bug no formulário"
git commit -m "docs: atualiza README"
    Convenção: Use prefixos como feat:, fix:, docs:, style:, refactor: para organizar o histórico.
  • git push

    Envia os commits locais para o repositório remoto (GitHub, GitLab, etc.).

    git push
# ou com origem e branch explícitos:
git push origin main

# primeiro push de um novo branch:
git push -u origin meu-branch
Sequência completa típica
# 1. Ver o estado atual
git status

# 2. Adicionar tudo
git add .

# 3. Fazer o commit
git commit -m "feat: minha funcionalidade"

# 4. Enviar para o remoto
git push
Comandos úteis
git log --oneline   # histórico
git diff            # ver mudanças
git pull            # atualizar local
git restore .       # descartar mudanças
Primeiro uso
git config --global user.name "Seu Nome"
git config --global user.email "email@x.com"
git init            # iniciar repo

chmod

Permissões de arquivos no Linux/macOS

Notação textual — rwx

O que significa cada letra?

Cada arquivo tem 3 grupos de permissões: dono, grupo e outros.

Leitura
r
= 4
Escrita
w
= 2
Execução
x
= 1
Negado
-
= 0
# Como ler a saída de: ls -l
#  tipo  dono   grupo  outros
-rwx  r--  ---   arquivo.sh
drwx  r-x  r-x   pasta/
Notação numérica (octal)

Tabela de valores

Número Bits rwx Permissões Descrição
7 rwx 4+2+1 Leitura + Escrita + Execução tudo
6 rw- 4+2 Leitura + Escrita comum para arquivos
5 r-x 4+1 Leitura + Execução comum para pastas
4 r-- 4 Só leitura read-only
3 -wx 2+1 Escrita + Execução
2 -w- 2 Só escrita
1 --x 1 Só execução raro
0 --- 0 Nenhuma permissão
Combinações mais usadas
# 755 — padrão para scripts e pastas
#       dono: rwx | grupo: r-x | outros: r-x
chmod 755 script.sh

# 644 — padrão para arquivos comuns
#       dono: rw- | grupo: r-- | outros: r--
chmod 644 arquivo.txt

# 600 — arquivo privado (só o dono lê/escreve)
chmod 600 chave-privada.pem

# 777 — todos têm tudo (evite em produção!)
chmod 777 arquivo
Notação simbólica (textual)
# u=user(dono), g=group, o=others, a=all
# + adiciona, - remove, = define

chmod u+x script.sh       # dá execução ao dono
chmod o-w arquivo.txt     # remove escrita dos outros
chmod a+r arquivo.txt     # leitura para todos
chmod g=rx pasta/          # grupo: somente r e x

# Recursivo (aplica em todos os arquivos da pasta)
chmod -R 755 minha-pasta/
⚠️ Cuidado com 777: Dar permissão total a todos os usuários é um risco de segurança. Use apenas localmente para testes. Em servidores, prefira 644 para arquivos e 755 para pastas e scripts.

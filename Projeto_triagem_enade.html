Fila de Triagem: Listas Encadeadas com Prioridade

Questão discursiva sobre estrutura de dados aplicada a um sistema hospitalar de classificação de risco — do enunciado ao circuito físico.

Cartão verde = menor urgência Cartão amarelo = maior urgência Estrutura: lista simplesmente encadeada
01 · O caso

O cenário da triagem

Um hospital organiza o atendimento com uma fila de prioridade simples: cada paciente recebe, na triagem, um cartão verde (casos menos urgentes) ou um cartão amarelo (casos mais urgentes). A fila deve refletir essa prioridade — mas sem embaralhar a ordem de chegada dentro de cada grupo.

A regra de organização é: pacientes verdes entram sempre no final da fila, na ordem em que chegam. Pacientes amarelos furam a fila dos verdes, mas respeitam a ordem de chegada entre os próprios amarelos — ou seja, um amarelo novo entra depois dos amarelos que já estão na fila, e antes de todos os verdes.

Considerando a chegada, nessa ordem, dos pacientes 10-V, 11-V, 5-A, 12-V e 6-A, a fila final deve ficar assim organizada:

5URGENTE
6URGENTE
10ROTINA
11ROTINA
12ROTINA

A tarefa da questão é implementar a função que faz essa inserção com prioridade — a peça que falta no código-fonte fornecido.

02 · Leitura do código

O que o código-fonte já traz pronto

O software de triagem usa uma lista simplesmente encadeada, onde cada nó guarda o número do paciente e a cor do cartão:

struct lista {
    int numero;
    char cor;
    struct lista* prox;
};
typedef struct lista Lista;
inserir_fim
Percorre a lista até o último nó (aquele cujo prox é NULL) e encadeia o novo paciente ali. É assim que os cartões verdes entram — sempre no final, respeitando a ordem de chegada.
inserir
Função de entrada: recebe número e cor, aloca o nó e decide o destino. Lista vazia → o novo nó vira a cabeça. Caso contrário, delega para inserir_fim (se for 'V') ou para inserir_prioridade (se for 'A') — esta última é a que falta implementar.

Ou seja: o comportamento dos cartões verdes já está garantido pelo código existente. O que falta é ensinar a lista a inserir um cartão amarelo na frente dos verdes, mas atrás dos amarelos que já chegaram antes.

03 · A solução

Implementando inserir_prioridade

A lógica tem só dois casos:

Caso 1 — a cabeça da lista não é amarela (lista vazia, ou o primeiro nó já é verde). Nesse caso o novo cartão amarelo vira a nova cabeça, na frente de tudo.

Caso 2 — a cabeça já é amarela. Aí é preciso andar pela lista enquanto o próximo nó também for amarelo, parando assim que encontrar o fim do bloco de amarelos (seja porque chegou a um verde, seja porque chegou ao fim da lista). O novo nó é encaixado logo ali.

Lista* inserir_prioridade(Lista* l, Lista* no) {
    Lista* aux;

    if (l == NULL || l->cor == 'V') {
        // fila vazia ou começa com verde: o amarelo assume a cabeça
        no->prox = l;
        l = no;
    } else {
        // avança enquanto o nó seguinte também for amarelo
        aux = l;
        while (aux->prox != NULL && aux->prox->cor == 'A')
            aux = aux->prox;

        no->prox = aux->prox;
        aux->prox = no;
    }

    return l;
}

04 · Da tela para a bancada

Implementação física com Arduino Uno e LEDs

A mesma lógica roda literalmente no Arduino (a AVR libc tem malloc, então a struct e as funções não mudam nada). Cada posição da fila vira um par de LEDs — verde e amarelo — e só um deles acende, indicando a cor do cartão que está ali. Um botão avança a simulação, inserindo o próximo paciente da sequência.

Cada LED liga em pino digital → resistor de 220Ω → LED → GND. A cada clique no botão, o Arduino insere o próximo paciente da sequência de teste, percorre a lista e reacende os LEDs na ordem correta — reproduzindo fisicamente o diagrama da questão. O número de cada paciente é impresso no Serial Monitor, já que os LEDs sozinhos não mostram números.

Núcleo da lógica no firmware

void atualizarLEDs() {
    // apaga tudo, depois percorre a lista e acende
    // o LED correspondente à cor de cada nó, posição a posição
    Lista* aux = fila;
    int pos = 0;
    while (aux != NULL && pos < NUM_SLOTS) {
        if (aux->cor == 'V')
            digitalWrite(pinVerde[pos], HIGH);
        else
            digitalWrite(pinAmarelo[pos], HIGH);
        aux = aux->prox;
        pos++;
    }
}

O sketch completo (com inserir, inserir_fim, inserir_prioridade e o tratamento do botão com debounce) é o mesmo triagem_leds.ino já preparado — é só copiar direto pro Arduino IDE.

05 · Resposta documentada

Gabarito comentado

Padrão de resposta oficial

A banca resume a lógica esperada em dois fundamentos de inserção em lista simplesmente encadeada, avaliados de forma independente:

  • Inserção no início: se ainda não há nenhum cartão amarelo na fila (ou seja, a cabeça atual já é verde), o novo nó é inserido como primeiro elemento.
  • Inserção no meio ou no fim: se já existem cartões amarelos, o novo nó entra logo depois do último deles — seja porque em seguida vem um verde (inserção no meio), seja porque a lista termina ali (inserção no fim). A lógica de inserção é a mesma para os dois casos; o que muda é só até onde o percurso avança.

A banca observa ainda que é aceita qualquer linguagem de programação ou pseudo-código, desde que compatível com essa lógica.

Código do padrão oficial (INEP)

Lista* inserir_prioridade(Lista* l, Lista* no) {
    if (l->cartao == 'V') {
        no->prox = l;
        l = no;
    } else {
        Lista* ant = l;
        Lista* aux = ant->prox;
        while (aux != NULL && aux->cartao == 'A') {
            ant = aux;
            aux = aux->prox;
        }
        ant->prox = no;
        no->prox = aux;
    }
    return l;
}

Repare que a banca não testa l == NULL: olhando a função inserir do enunciado, inserir_prioridade só é chamada dentro do ramo else, ou seja, quando a lista já tem pelo menos um nó. Note também que o campo aparece como cartao no gabarito — no código-fonte original da questão esse mesmo campo se chama cor; é só uma troca de nome, o comportamento é idêntico.

Comparando com a versão implementada aqui

A versão que construímos usa um único ponteiro auxiliar com "olhar à frente" (aux->prox->cor == 'A') em vez do par ant/aux do gabarito oficial. São duas formas igualmente corretas de resolver o mesmo problema:

AbordagemComo percorreComo insere
Gabarito oficial (ant/aux)aux avança; ant guarda o nó anteriorant->prox = no; no->prox = aux;
Versão desta página (1 ponteiro)aux avança olhando aux->prox antes de moverno->prox = aux->prox; aux->prox = no;

Ambas param exatamente no mesmo nó e produzem a mesma fila final — a diferença é só estilística (uma variável a menos, ao custo de olhar um passo à frente na condição do laço). Numa correção discursiva, as duas versões atendem integralmente aos dois fundamentos exigidos pelo padrão de resposta.

Complexidade: O(n) no pior caso em ambas as versões, pois a função pode precisar percorrer todos os cartões amarelos já inseridos antes de encontrar o ponto de inserção — mesma ordem de grandeza de inserir_fim.

Erros comuns que a banca costuma penalizar: testar apenas a lista vazia e esquecer o caso "cabeça já é verde" (faz o primeiro amarelo ser inserido no lugar errado); inverter a ordem de religação dos ponteiros (perde a referência ao restante da lista); ou, na versão com olhar à frente, usar aux->cor == 'A' em vez de aux->prox->cor == 'A' na condição do laço — o que faz o ponteiro avançar um nó a mais e insere na posição errada.

Aula 03 — Arquivos Estáticos

CSS · Imagens · JavaScript · {% static %}

📚

O que são Arquivos Estáticos?

CSS, imagens e JS que não mudam dinamicamente

🎨 Estilos

Arquivos CSS

Toda a aparência visual do site: cores, fontes, layout, animações. Ficam em setup/static/styles/.

🖼️ Imagens

Imagens e assets

Logos, fotos, ícones, favicons. Ficam em setup/static/assets/.

📂 Estrutura de pastas

setup/
└── static/             # Pasta principal dos estáticos
    ├── styles/
    │   └── style.css
    └── assets/
        ├── logo/

        ├── favicon/

Configurando no settings.py

Três variáveis essenciais para os estáticos

📋 As três configurações

settings.py — seção de static files

# setup/settings.py

# URL base para acessar os estáticos no browser
STATIC_URL = 'static/'

# Onde ficam os estáticos durante o desenvolvimento
STATICFILES_DIRS = [
    os.path.join(BASE_DIR, 'setup/static')
]

# Onde o Django coleta tudo ao rodar collectstatic
STATIC_ROOT = os.path.join(BASE_DIR, 'static')
STATICFILES_DIRS

Onde você coloca os arquivos

Pasta onde você edita/adiciona CSS e imagens durante o desenvolvimento. O Django busca aqui.

STATIC_ROOT

Onde o Django junta tudo

Pasta gerada pelo comando collectstatic. Não edite aqui — é gerada automaticamente.

🔧 Coletando os estáticos

python manage.py collectstatic

# Faz o Django reconhecer todos os arquivos estáticos
python manage.py collectstatic

Execute este comando após adicionar novos arquivos estáticos. Ele cria/atualiza a pasta static/ na raiz do projeto.

🏷️

Usando Estáticos no HTML

{% load static %} e {% static '...' %}

1️⃣ Carregar o módulo

Primeira linha do template

<!-- Sempre na PRIMEIRA linha do arquivo HTML -->
{% load static %}

<!DOCTYPE html>
<html lang="pt-BR">
...
2️⃣ Referenciar arquivos estáticos

Substituindo caminhos fixos

Ao invés de usar caminhos relativos no HTML, use a tag {% static %}:

<!-- ❌ ERRADO — caminho fixo que pode quebrar -->
<link rel="stylesheet" href="styles/style.css">

<!-- ✅ CERTO — usa a tag do Django -->
<link rel="stylesheet" href="{% static 'styles/style.css' %}">

<!-- Para imagens -->
<img src="{% static 'assets/logo/logo.png' %}" alt="Logo">

<!-- Para favicon -->
<link rel="icon" href="{% static 'assets/favicon/favicon.png' %}">
🖼️ Imagens dinâmicas do banco de dados

Combinando {% static %} com variáveis Django

Para imagens cujo nome vem do banco de dados, combine a tag static com a variável:

<!-- A pasta é estática, o nome do arquivo vem do banco -->
<img 
  src="{% static 'assets/imagens/galeria/' %}{{fotografia.foto}}" 
  alt="{{fotografia.nome}}"
>
💡

Note que o {% static %} gera o caminho da pasta, e depois concatenamos com o nome do arquivo que vem do banco de dados via {{fotografia.foto}}.

🔗

Navegação Entre Páginas

{% url %} — links dinâmicos

⚡ {% url %} vs href fixo

A forma correta de criar links no Django

<!-- ❌ Link fixo — se mudar a URL, quebra -->
<a href="imagem.html">Ver imagem</a>
<a href="/imagem/">Ver imagem</a>

<!-- ✅ Link dinâmico — usa o name da URL -->
<a href="{% url 'imagem' %}">Ver imagem</a>
<a href="{% url 'index' %}">Home</a>

<!-- Passando parâmetro (foto_id) -->
<a href="{% url 'imagem' fotografia.id %}">Ver detalhes</a>
🔢 URL com parâmetro dinâmico

Passando o ID da foto na URL

Para que cada foto tenha sua própria URL (/imagem/1/, /imagem/2/, etc.), configure assim:

# galeria/urls.py
urlpatterns = [
    path('', index, name='index'),
    path('imagem/<int:foto_id>', imagem, name='imagem'),
]
# galeria/views.py — recebe o foto_id
from django.shortcuts import render, get_object_or_404
from galeria.models import Fotografia

def imagem(request, foto_id):
    fotografia = get_object_or_404(Fotografia, pk=foto_id)
    return render(request, 'galeria/imagem.html', {'fotografia': fotografia})
📌 get_object_or_404

Tratamento automático de erros

O get_object_or_404() busca o objeto no banco de dados. Se não encontrar, automaticamente retorna uma página de erro 404 — muito mais elegante que deixar o Django quebrar!

🛡️

pk = Primary Key — é o ID único de cada item no banco de dados. No Django, todo model tem um campo id gerado automaticamente que serve como chave primária.

Controle de Empréstimo com RFID

Opção 1 — A mais recomendada para integração real

⭐

Por que essa é a melhor escolha?

RFID + Django + API REST é o equilíbrio perfeito entre prática, inovação e aplicabilidade real. O aluno sai sabendo conectar hardware com software — habilidade valorizada no mercado.

Como funciona

Fluxo do sistema

Tag RFID no livro / cartão do aluno
Cada livro e cada aluno tem uma tag RFID única identificada por UID
Aluno aproxima o cartão do leitor
O leitor RC522 lê o UID e envia para o ESP32/Arduino via SPI
ESP32 faz POST para a API Django
Envia JSON com UID do aluno + UID do livro via WiFi (HTTP)
Django registra o empréstimo automaticamente
Cria registro no banco, retorna confirmação, atualiza dashboard
Hardware necessário

Componentes

  • 🧠ESP32 — microcontrolador com WiFi integrado recomendado
  • 📟Arduino Uno/Mega — alternativa sem WiFi nativo alternativa
  • 📡Leitor RFID RC522 — comunicação SPI, 3.3V, módulo barato (~R$15)
  • 🏷️Tags RFID MIFARE 13.56MHz — cartões ou etiquetas adesivas para os livros
  • 💡LED + Buzzer — feedback visual/sonoro ao fazer leitura
Código — ESP32 (MicroPython)
# ESP32 — envia leitura RFID para API Django
import network, urequests, mfrc522, json

# Conectar ao WiFi
wlan = network.WLAN(network.STA_IF)
wlan.active(True)
wlan.connect("SSID_DA_REDE", "SENHA")

# URL da API Django (IP local ou domínio)
API_URL = "http://192.168.1.100:8000/api/emprestimo/"

# Loop principal — aguarda leitura RFID
while True:
    uid_aluno = ler_rfid()   # lê cartão do aluno
    uid_livro = ler_rfid()   # lê tag do livro

    payload = {
        "uid_aluno": uid_aluno,
        "uid_livro": uid_livro
    }

    # POST para o Django
    resp = urequests.post(
        API_URL,
        data=json.dumps(payload),
        headers={"Content-Type": "application/json"}
    )

    if resp.status_code == 201:
        bip_sucesso()   # feedback sonoro
    else:
        bip_erro()      # aluno não cadastrado
Código — Django (models.py)
# biblioteca/models.py
from django.db import models

class Aluno(models.Model):
    nome = models.CharField(max_length=100)
    uid_rfid = models.CharField(max_length=50, unique=True)
    matricula = models.CharField(max_length=20)

class Livro(models.Model):
    titulo = models.CharField(max_length=200)
    uid_rfid = models.CharField(max_length=50, unique=True)
    disponivel = models.BooleanField(default=True)

class Emprestimo(models.Model):
    aluno = models.ForeignKey(Aluno, on_delete=models.CASCADE)
    livro = models.ForeignKey(Livro, on_delete=models.CASCADE)
    data_retirada = models.DateTimeField(auto_now_add=True)
    data_devolucao = models.DateTimeField(null=True, blank=True)
    ativo = models.BooleanField(default=True)
Código — Django (views.py / API)
# biblioteca/views.py
from django.http import JsonResponse
from django.views.decorators.csrf import csrf_exempt
import json

@csrf_exempt
def registrar_emprestimo(request):
    if request.method != 'POST':
        return JsonResponse({'erro': 'Método inválido'}, status=405)

    dados = json.loads(request.body)
    uid_aluno = dados.get('uid_aluno')
    uid_livro = dados.get('uid_livro')

    try:
        aluno = Aluno.objects.get(uid_rfid=uid_aluno)
        livro = Livro.objects.get(uid_rfid=uid_livro, disponivel=True)
    except (Aluno.DoesNotExist, Livro.DoesNotExist):
        return JsonResponse({'erro': 'Não encontrado'}, status=404)

    Emprestimo.objects.create(aluno=aluno, livro=livro)
    livro.disponivel = False
    livro.save()

    return JsonResponse({
        'mensagem': 'Empréstimo registrado!',
        'aluno': aluno.nome,
        'livro': livro.titulo
    }, status=201)

Sensores usados

Para que serve
  • Conservação do acervo (temperatura e umidade ideais para livros)
  • Estatísticas de uso da biblioteca (sensor de presença)
  • Dashboard com histórico de leituras
  • Alertas automáticos via email/SMS quando limites são ultrapassados
Código — ESP32 + DHT22
# ESP32 — envia dados de temperatura e umidade
import dht, machine, urequests, time

sensor = dht.DHT22(machine.Pin(4))
API_URL = "http://192.168.1.100:8000/api/sensor/"

while True:
    sensor.measure()
    payload = {
        "temperatura": sensor.temperature(),
        "umidade":     sensor.humidity()
    }
    urequests.post(API_URL, json=payload)
    time.sleep(60)  # envia a cada 1 minuto

Controle de Acesso

Opção 3 — Porta da biblioteca com RFID ou senha

Como funciona

Fluxo de entrada na biblioteca

Aluno aproxima cartão RFID ou digita senha
Na entrada física da biblioteca / sala
ESP32 consulta a API Django
Verifica se o UID está cadastrado e tem acesso liberado
Django responde: liberado ou negado
Consulta o banco de dados de alunos cadastrados
Trava solenoide abre / LED indica status
ESP32 aciona o relé que controla a trava da porta
Hardware adicional
  • 🔒 Trava solenoide 12V — abre com sinal elétrico
  • ⚡ Módulo relé 5V — ESP32 controla a trava
  • 🔢 Teclado matricial 4x4 — alternativa ao RFID (senha)
  • 📺 Display LCD I2C — mostra nome do aluno ao entrar
Integração com Django
# biblioteca/views.py — endpoint de verificação de acesso
@csrf_exempt
def verificar_acesso(request):
    dados = json.loads(request.body)
    uid = dados.get('uid')

    try:
        aluno = Aluno.objects.get(uid_rfid=uid, ativo=True)
        # Registra o acesso no log
        RegistroAcesso.objects.create(aluno=aluno)
        return JsonResponse({
            'acesso': True,
            'nome': aluno.nome
        })
    except Aluno.DoesNotExist:
        return JsonResponse({'acesso': False}, status=403)
Integração com autenticação Django
  • Usa o mesmo sistema de usuários do Django (django.contrib.auth)
  • Histórico de acesso por aluno acessível no admin
  • Possível integrar com o sistema de empréstimos (só quem entrou pode retirar)
  • Dashboard mostrando quem está na biblioteca em tempo real

Checklist para os alunos

Grupo 1 — Backend

  • Criar projeto Django
  • Definir models (Aluno, Livro, Emprestimo)
  • Configurar admin
  • Conectar PostgreSQL
  • Popular banco com dados de teste

Grupo 2 — API

  • Criar endpoints POST/GET
  • Testar com Postman/Insomnia
  • Retornar JSON correto
  • Tratar erros (404, 405)
  • Documentar as rotas

Grupo 3 — IoT

  • Montar circuito RFID + ESP32
  • Ler UID das tags
  • Conectar ESP32 ao WiFi
  • Fazer POST para a API
  • Testar feedback (LED/buzzer)

Grupo 4 — Frontend

  • Criar template dashboard
  • Listar empréstimos ativos
  • Mostrar estatísticas
  • Estilizar com Bootstrap/CSS
  • Atualizar dados em tempo real
⚠️ Erros comuns — evite isso
  • Usar IoT só para "piscar LED" — não agrega valor pedagógico real
  • Não integrar o hardware com o sistema principal — vira projeto separado
  • Complicar demais (MQTT + cloud + mil dependências) — perde a didática
  • Não testar a API antes de conectar o hardware — dificulta o debug
  • Grupos trabalhando em silos sem comunicar as interfaces entre si

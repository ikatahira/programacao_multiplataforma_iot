Herança de Templates

Evite repetição com extends e block

❓ O problema

Por que herança de templates?

Sem herança, cada página HTML repete o mesmo cabeçalho, menu e rodapé. Se você precisar alterar o menu, terá que editar todos os arquivos. A herança resolve isso: você define o layout em um único arquivo base e as outras páginas apenas preenchem os "buracos" (blocos).

💡

Analogia: o base.html é como uma moldura de quadro. Cada página é uma tela diferente colocada dentro da mesma moldura.

📄 base.html

Criando o template base

Crie o arquivo templates/galeria/base.html com a estrutura comum a todas as páginas:

<!-- templates/galeria/base.html -->
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8">
  <title>Space Gallery</title>
</head>
<body>
  <nav>
    <a href="/">Início</a>
  </nav>

  {# Bloco que cada página vai preencher #}
  {% block conteudo %}{% endblock %}

  <footer>Space Gallery © 2024</footer>
</body>
</html>
📄 index.html

Página filha — usando extends

Agora, qualquer página que herdar do base não precisa repetir a estrutura. Apenas preenche o bloco:

<!-- templates/galeria/index.html -->

{# 1. Indica qual é o template pai #}
{% extends 'galeria/base.html' %}

{# 2. Preenche o bloco definido no base #}
{% block conteudo %}
  <h1>Bem-vindo à galeria!</h1>
  <p>Fotos incríveis do espaço.</p>
{% endblock %}
⚠️

Regra importante: o {% extends %} deve ser a primeira linha do arquivo. Nada pode vir antes dele.

🧱 Múltiplos blocos

Você pode ter quantos blocos quiser

<!-- base.html com múltiplos blocos -->
<head>
  {% block titulo %}Space Gallery{% endblock %}
  {% block estilos %}{% endblock %}
</head>
<body>
  {% block conteudo %}{% endblock %}
  {% block scripts %}{% endblock %}
</body>

Partials com {% include %}

Componentes reutilizáveis nos templates

❓ O que são partials

Fragmentos de HTML reutilizáveis

Partials são pedaços de template que você extrai para arquivos separados e inclui onde quiser. A convenção é nomear com underscore: _menu.html, _footer.html. O underscore sinaliza que o arquivo não é uma página completa, mas um fragmento.

📄 Exemplo — menu

Criando e incluindo um partial

<!-- templates/galeria/partials/_menu.html -->
<nav class="menu">
  <a href="/">Início</a>
  <a href="/buscar">Buscar</a>
</nav>
<!-- Dentro do base.html — incluindo o partial -->
<body>
  {% include 'galeria/partials/_menu.html' %}

  {% block conteudo %}{% endblock %}
</body>
💡

Partials têm acesso automático às variáveis de contexto da view. Não é preciso passar nada extra.

📁 Estrutura recomendada

Como organizar os templates

templates/
  galeria/
    base.html          # layout base
    index.html         # página principal
    imagem.html        # página de detalhe
    partials/
      _menu.html       # fragmento: menu
      _footer.html     # fragmento: rodapé
      _card_foto.html  # fragmento: card de foto

Tag {% url %}

Links dinâmicos sem hardcode

❓ O problema do hardcode

Por que não usar URLs fixas?

Se você escrever <a href="/galeria/index"> e depois mudar a rota no urls.py, terá que atualizar todos os templates manualmente. A tag {% url %} gera o link automaticamente a partir do nome da URL.

⚙️ Configurando nomes nas URLs

Passo 1 — nomear as rotas no urls.py

# galeria/urls.py
from django.urls import path
from galeria import views

urlpatterns = [
    path('', views.index, name='index'),
    path('imagem/<int:foto_id>/', views.imagem, name='imagem'),
    path('buscar/', views.buscar, name='buscar'),
]
🏷️ Usando no template

Passo 2 — gerar links com {% url %}

<!-- Link simples — sem parâmetros -->
<a href="{% url 'index' %}">Início</a>

<!-- Link com parâmetro (id da foto) -->
<a href="{% url 'imagem' foto.id %}">Ver foto</a>

<!-- Formulário de busca -->
<form action="{% url 'buscar' %}">
  <input type="text" name="buscar">
</form>
💡

Se a URL mudar no urls.py, todos os links nos templates são atualizados automaticamente. Zero manutenção.

Tags for e if

Lógica e repetição nos templates

🔄 {% for %}

Iterando sobre listas e querysets

Use {% for %} para percorrer qualquer lista ou queryset passado pelo contexto da view:

<!-- Listar todas as fotos -->
{% for fotografia in fotografias %}
  <div class="card">
    <h2>{{ fotografia.nome }}</h2>
    <p>{{ fotografia.descricao }}</p>
  </div>
{% endfor %}

<!-- Caso a lista esteja vazia -->
{% for fotografia in fotografias %}
  {{ fotografia.nome }}
{% empty %}
  <p>Nenhuma foto encontrada.</p>
{% endfor %}
🔢 Variáveis do forloop

Informações automáticas dentro do loop

{% for foto in fotografias %}
  {# Número do item (começa em 1) #}
  {{ forloop.counter }}

  {# True se for o primeiro item #}
  {{ forloop.first }}

  {# True se for o último item #}
  {{ forloop.last }}
{% endfor %}
❓ {% if %}

Lógica condicional no template

<!-- Condicional simples -->
{% if fotografia.publicada %}
  <span>Publicada</span>
{% else %}
  <span>Não publicada</span>
{% endif %}

<!-- Com elif -->
{% if fotografia.categoria == 'NEBULOSA' %}
  <span class="badge-purple">Nebulosa</span>
{% elif fotografia.categoria == 'ESTRELA' %}
  <span class="badge-yellow">Estrela</span>
{% else %}
  <span class="badge-blue">Outro</span>
{% endif %}
💬 Comentários

Comentários que não aparecem no HTML

{# Este comentário NÃO aparece no HTML final #}
<!-- Este SIM aparece no HTML final -->
